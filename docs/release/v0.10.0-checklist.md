# ASC v0.10.0 — 릴리스 체크리스트 (minor · 정상 경로가 advanced primitive 없이 닫힌다)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).
finalize 는 이 파일의 `## 실행 기록` 섹션이 `main` 에 있어야 돈다.

## 이 릴리스가 싣는 것

0.9.1 제품 dogfood(2026-09-13, 자연어 → MR 관통)에서 사람이 알아야 했던 일곱 가지를 그 층에서 닫는다.

```text
#89  P1  ACTION_PAYLOAD (required/optional/forbidden) · git.push 본문 거절(exit 2) · Core 는 payloadRequired 입력
         setup 이 local 승인자 후보를 발견 → ASC_LOCAL_IDENTITY_REQUIRED (자동 권한 부여 없음) · gate 가 local 검사
         --as 는 local 승인자 정확히 1명일 때만 생략 · 건네는 명령 shell-quote
     P2  core/operator/blockers.ts (semantic remediation) · cli/remediation.ts 표 하나 · status Blocked:/Next: · CONFLICT stdout
     P3  ContractProposal (CREATED→ISSUED|REVISED|REJECTED|OBSOLETE, adapters/proposals) · asc work issue · setup delegate
         발급 기록 authority/delegatedBy/issuedBy/recordedBy 분리
     P4  asc work reclaim (근거 → 사람이 인수) · terminal-holder audited RELEASED
     P5  exact key · 빈 가지 · IN_PROGRESS_ELSEWHERE · off-target 언급 → UNDECIDABLE · --fresh override 기록
```

Core 에 provider 의미 없음. Guard/F6/셸 interception 없음. 새 opaque 없음. resource identity·multi-binding·GitHub review·canonicalProposal·alias 제거·guard rename 은 **이번 주제 밖** (변경 없음).

## Gate (publish 전)

```text
[ ] npm run typecheck / build / test          — 1727 / 1726 pass / 0 fail / 1 skip
[ ] npm run release:check                     — 0.10.0 명명·note 섹션·버전 리터럴
[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check                — 비게이트
[ ] 3-OS CI green on main                     — #89 · release PR
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize
```

## Published acceptance (게시본으로만 · 실 workspace)

0.9.0 A-1~A-12(managed git.push 관통)·0.9.1 P-1~P-6 은 되풀이하지 않는다 — executor·GitLab·binding-identity 경로는
이 회차가 건드리지 않았다. 이 회차가 바꾼 것만, **실제 제품 작업으로** 본다. 사전 상태(identities·override·lock·
binding 수·inbox 수)를 D-0 에 적고 종료 후 비교한다. cleanup 은 acceptance 와 분리한다.

```text
[ ] D-0  사전 상태 기록 (macOS 실기계, 실 제품 workspace)
[ ] Q-1  asc update 0.9.1 → 0.10.0 · asc setup 이 두 질문(local identity / delegation)을 차례로 한 번씩 묻고,
         답이 identities.json / override.json 에 남고 재고정된다 · 그 뒤 already_configured
[ ] Q-2  작업 A' (MANUAL, 미착수 FE 1건): 자연어 → work start → CLAIMED → 구현 → publish git.push (--body-file·--as 없이)
         → gitlab.mr.create → finish.  사람이 알아야 한 내부 primitive 0 · T 멈춤 0
[ ] Q-3  작업 B' (AUTO, 동등 1건): 같은 경로. 비교표: 사람 추가 행위 · 멈춤 수 · boundary 수 · primitive 노출 · publish/verify/finish 차이
         (동등 작업이 없으면 not taken 으로 남긴다 — 다른 작업으로 대체하지 않는다)
[ ] Q-4  비위임 (setup delegate --none → 재고정): work start 가 proposal 저장 + "asc work issue S-…" 한 줄 → 사람이 그 한 줄 → READY → CLAIMED
[ ] Q-5  status: LOCK_DRIFT 를 인위로 만들어 Blocked:/Next: 와 work start stderr 가 같은 remedy · local 항목 제거 → approval BLOCKED 로 보임 (원복)
[ ] Q-6  WORK_STATE: 다른 worktree 진행 중 항목 → IN_PROGRESS_ELSEWHERE · 빈 가지 → 구현됨으로 읽지 않음 ·
         키 뒤바뀐 항목 → UNDECIDABLE(implementation-evidence) · --fresh 1회 → history 기록
[ ] R-2  recovery(별도, 판정에 안 씀): 타 Run 보유 상태에서 work start → stdout 소유권 없음 + reclaim 안내 → work reclaim → evidence·rebind·finish
[ ] Q-7  Windows 실기계: 0.9.1 → 0.10.0 asc update · setup 두 질문 · work reclaim 1회   (CI 로 대체 금지. 못 하면 not taken)
[ ] D-10 원복 · 외부 잔여물 목록 (MR 만)
```

Q-2 가 이 회차의 본체다. 합격 = Q-2(·Q-3) 에서 사람이 알아야 한 내부 primitive 0 · T 멈춤 0 · status 가 매 막힘에 이유+다음 행동 1개.
Q-2/Q-3 는 **새 Claude 세션(다른 Run)** 에서 시작해 SessionStart 복원이 뜨는지 함께 본다 (0.9.1 미확인 N6).

```text

```
