# ASC v0.2.0 — release checklist

This is a procedure, not a script. **Nothing here publishes on its own.** Each step below
the human boundary is run deliberately, in order, by a person.

Contract: [C-14](../contracts/C-14_distribution-runtime-entry.md).
Predecessor: [v0.1.0 checklist](v0.1.0-checklist.md) — executed, kept as the record.

## What this release is

v0.1.0 was something one person could install. It could not be handed to a team, because a
profile describing a real project had nowhere to live except inside the package — and an
agent given only the repository URL could not get past that.

```text
external profiles     a profile lives in $ASC_HOME/profiles/ and is found there
profile adopt         a profile is made from the repository you are in
agent entry           AGENTS.md — the ordered path, with the decisions already made
published reality     the documentation stops claiming the packages are unpublished
```

## Why the order is fixed

`@asc-agent/bootstrap` depends on `@asc-agent/runtime` at an **exact** version. If
bootstrap goes to the registry first, the very first `npx --yes @asc-agent/bootstrap@0.2.0`
resolves a dependency that does not exist yet, and the first thing anyone sees is a broken
install.

```text
runtime → verify on the registry → bootstrap → verify → real E2E → tag → release
```

Do not reorder this.

## Before the boundary — repeatable, safe to run any time

```text
[ ] main is clean, and origin/main...HEAD is 0 0
[ ] CI green on main
[ ] npm run typecheck
[ ] npm test
[ ] npm run build
[ ] npm run release:check
[ ] npm run pack:all
[ ] npm run smoke            includes the zero-base acceptance sequence
[ ] npm publish --dry-run   in packages/runtime
[ ] npm publish --dry-run   in packages/bootstrap
[ ] tarball contains no tests, no raw .ts, no docs, no credentials, no machine paths
[ ] tarball carries only the public example profiles — no real project's profile
```

Upgrade safety, because people are already on 0.1.0:

```text
[ ] a 0.1.0 attachment keeps working after installing 0.2.0 — no re-attach
[ ] profile digest does not move for an unchanged profile (no LOCK_DRIFT)
[ ] an open session survives the upgrade and can still be driven
```

## HUMAN RELEASE BOUNDARY

Everything above changes nothing outside this machine. Everything below does, and most of
it cannot be undone.

## Publishing

```text
[ ] publish @asc-agent/runtime@0.2.0
        cd packages/runtime && npm publish
[ ] npm view @asc-agent/runtime@0.2.0 version dist.tarball
[ ] registry runtime smoke — isolated prefix:
        npm install -g @asc-agent/runtime@0.2.0
        asc --help
        asc setup status

[ ] publish @asc-agent/bootstrap@0.2.0
        cd packages/bootstrap && npm publish
[ ] npm view @asc-agent/bootstrap@0.2.0 version dependencies
```

## Real registry end-to-end — the two-URL run

This is the one that decides whether the release did its job. Run it in a sandbox that
borrows nothing: isolated `HOME`, `ASC_HOME`, npm cache, npm prefix, and a git project that
is **not** this repository.

Give a zero-base agent session the repository URL and "apply this", nothing else. It must
reach a running session without asking a single question that AGENTS.md already answers.

```text
[ ] npx --yes @asc-agent/bootstrap@0.2.0 init --agent
        bootstrap is fetched from the registry
        the plan lists runtime-install
        the stop is ASC_PROFILE_SELECTION_REQUIRED, and it changed nothing
[ ] the agent runs the adopt_profile action's portable command, unedited
[ ] a profile appears under ~/.asc/profiles/, describing that project
[ ] setup apply --agent attaches; remaining is empty
[ ] setup status --json reports attachment READY, profile origin external
[ ] session issue + session start succeed while gates are still BLOCKED
[ ] repository footprint is 0
[ ] no question was put to the human except secrets, permissions or an irreversible action
```

Until this passes against the real registry, the two-URL path stays **TEST_VERIFIED** on
tarballs only. The tarball smoke does not observe the registry, and saying otherwise would
blur the two levels.

## Tag and release

```text
[ ] git tag -a v0.2.0 -m "ASC v0.2.0"
[ ] git push origin v0.2.0
[ ] GitHub Release for v0.2.0
```

## After publishing

**0.2.0 is immutable.** If the registry end-to-end finds a defect, it is fixed in 0.2.1 —
a published version is never re-published or overwritten, because someone may already have
installed it and a silently different 0.2.0 is worse than a visible 0.2.1.

```text
[ ] defect found after publish → 0.2.1, never a re-publish of 0.2.0
[ ] docs/status.md records the registry observation at its real level
```
