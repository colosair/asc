## What this release is

v0.2.0 proved an agent could go from a repository URL to a running session — when it was
allowed to start the process at all. Re-running that on a real machine, the host refused to
execute the bootstrap command before any ASC code ran. This release is about the two things
that sit *before* ASC: whether the command can start, and whether this Node can run it.

```text
canonical agent entry   one command, ending in --json, for every agent-facing path
portable actions        every actions[].portable now answers in JSON, as promised
host boundary           HOST_EXECUTION_PERMISSION_REQUIRED named in AGENTS.md, with a
                        minimal permission recipe and a no-brute-force rule
node prerequisite       NODE_RUNTIME_REQUIRED — deterministic, with candidates found
executionMode           the installed `asc` stops calling itself bootstrap
```

## Behaviour changes to say out loud

```text
Node < 24 now fails.   It used to warn (npm EBADENGINE) and then run anyway. `engines` has
                       said >=24 since 0.1.0; now the answer is the same either way.
                       Anyone running ASC on Node 22 today will see NODE_RUNTIME_REQUIRED,
                       with the newer Node on their machine named if it can be found.
--agent is undocumented. Still accepted, still byte-identical to --json apply, and one
                       test keeps it alive. It is gone from every document and every
                       string ASC emits.
portable strings gain --json. An agent that stored a portable from 0.2.0 and replays it
                       still works; the new form is what the plan now hands out.
```

## Why the order is fixed

`@asc-agent/bootstrap` depends on `@asc-agent/runtime` at an **exact** version. If
bootstrap goes to the registry first, the very first `npx --yes @asc-agent/bootstrap@0.2.1`
resolves a dependency that does not exist yet, and the first thing anyone sees is a broken
install.

```text
runtime → verify on the registry → bootstrap → verify → real E2E → tag → release
```

Do not reorder this.

## Host observation — 9A, required before publishing

The defect that started this release is invisible to CI: it happens in a real Claude Code
auto-mode session, before any ASC process exists. It has to be watched, not asserted.

The classifier is **not deterministic** — a read-only `node -v` was denied in the same
session that allowed four `npx` commands. A single trial proves nothing; run each arm two
to three times, in a fresh auto-mode session, against the packed candidate.

Executed 2026-08-28. Results are recorded inline below, and in full in the evidence
repository.

```text
[x] Arm 1  canonical: npx --yes @asc-agent/bootstrap@0.2.1 setup apply --json
             DENIED 2/2 in one session — and ALLOWED in another session
[x] Arm 2  same command with --agent substituted for --json
             DENIED 2/2 — it does not separate from arm 1
[x] Arm 3  the node-gate form: PATH="<dir>:$PATH" <canonical>
             ALLOWED 2/2
[x] Arm 4  recovery
             exact allow rule for the command → still DENIED
             permission mode switched, same command re-run → one-shot approval → ALLOWED
             ASC started and answered ASC_PROFILE_SELECTION_REQUIRED, changesApplied false
[x] verdicts recorded per trial in the evidence repository
```

**No cause is established, and none is written down.** Arms 1 and 2 did not separate, so
`--agent` is not it. The same canonical command was denied twice in one session and allowed
in another, so neither Node nor the `PATH=` prefix can be claimed either — in this
environment the classifier is session-dependent or nondeterministic, and that is the whole
finding. What is established is the recovery: **an exact allow rule did not work; switching
the permission mode and approving the single run did.** AGENTS.md says exactly that and
nothing more.

## After publishing

**0.2.1 is immutable.** If the registry end-to-end finds a defect, it is fixed in 0.2.2 —
a published version is never re-published or overwritten, because someone may already have
installed it and a silently different 0.2.1 is worse than a visible 0.2.2.

```text
[ ] defect found after publish → 0.2.2, never a re-publish of 0.2.1
[x] docs/status.md records each observation at its real level, 9A and 9B kept apart
```
