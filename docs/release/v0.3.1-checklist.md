# ASC v0.3.1 — 릴리스 체크리스트 (emergency fallback + 인수 기록)

정본 경로는 `.github/workflows/release.yml` (tag push → OIDC publish)이다. 이 문서는
수동 fallback 절차와, 워크플로가 대신할 수 없는 인수 확인의 기록이다.

## 이 릴리스가 싣는 것

실전(SSAFESTA) 오판 사고의 P0 수정: Freshness Gate(stale 관측 위 ACTIONABLE 확정
금지), Evidence Adequacy(evidenceGrade·표현 제한·측정된 반증의 demote), 내용
등가(git cherry — 단일 커밋 squash·rebase·cherry-pick), Node self re-exec,
profile resolve 의 probe 실측 표시, skill 현황형 트리거, ASC_VERSION 하드코딩 제거.

## 업그레이드 주의 — LOCK_DRIFT 1회 발생

0.3.0 이하로 붙인 워크스페이스의 profile.lock 은 ascCore 를 0.2.1 로 기록하고
있다(하드코딩 잔존 버그). 0.3.1 은 실제 버전을 쓰므로 **첫 명령이 LOCK_DRIFT 로
멈춘다** — 이는 lock 철학대로의 정지이며, 확인 후 1회 복구한다:

```text
asc profile resolve --profile <id> --write
```

## Gate (publish 전 — 워크플로가 재실행하는 것과 동일)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check
[ ] npm run pack:all && npm run smoke
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → tag → GitHub Release
```

## Published acceptance (사람 몫)

```text
[ ] zero-install: npx --yes @asc-agent/bootstrap@0.3.2 → JSON
[ ] persistent: npm i -g @asc-agent/runtime@0.3.2 → asc 실행
[ ] Node re-exec: node22 기본 환경에서 asc 가 스스로 재실행되는가
[ ] SSAFESTA work ingress: fresh 관측(freshness FRESH)·증거 등급이 실작업에서 동작하는가
```
