# ASC v0.3.2 — 릴리스 체크리스트 (Windows 실전 결함 수정)

정본 경로는 `.github/workflows/release.yml` (tag push → OIDC publish)이다. 이 문서는
수동 fallback 절차와, 워크플로가 대신할 수 없는 인수 확인의 기록이다.

## 이 릴리스가 싣는 것

Windows fresh-install 실전 실측(2026-08-31)에서 잡힌 결함 수정:

- **ASC-7 (P0)** — Windows에서 npm `.cmd` shim CLI를 bare 이름으로 spawn해 host probe가
  "Claude Code: not found" → `external_write_guard` STOP으로 오판. `resolveExternalCommand`
  가 PATH의 `.exe` 직접 실행 / `.cmd` shim의 JS 진입점 추출 / `cmd.exe /d /c` 폴백으로
  세 OS에서 같은 의미로 부른다. host probe와 jam MCP client가 이 해석을 쓴다.
- **ASC-2** — 빈 `.asc/` skeleton을 attached로 읽어 `setup apply`가 `applied`를 답하며
  실패할 `proceed`를 다음 행동으로 제시. BROKEN attachment를 관측해 repair를 plan에 싣는다.
- **ASC-1** — `asc --version` / `asc version`. 모르는 옵션은 스택 대신 사용자 오류.
- **ASC-3·4·5·6** — role 오값 구분 안내, NOT_OWNER 복구 명령 제시, decision class 오값의
  선택지 안내(ZodError 원문 금지), done/pause owner 거부의 `--physical`·release 안내.
- **ASC-8 (무결 판정)** — capabilities evidence는 UTF-8 정상. 회귀 테스트로 고정.
  (이전 보고의 mojibake는 PowerShell 5.1 `Get-Content` ANSI 오독이었다.)

## Gate (publish 전 — 워크플로가 재실행하는 것과 동일)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check
[ ] npm run pack:all && npm run smoke
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → tag → GitHub Release
```

## Published acceptance (사람 몫)

```text
[ ] fresh Windows: npx --yes @asc-agent/bootstrap@0.3.2 setup apply --json
[ ] asc --version → 0.3.2
[ ] asc host claude probe → Claude Code 발견, external_write_guard 실측 판정 (STOP 오판 없음)
[ ] 빈 .asc/ skeleton에서 setup plan → repair가 계획에 실린다 (applied 오판 없음)
```
