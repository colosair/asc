# ASC v0.4.0 — 릴리스 체크리스트 (지속 제어면)

정본 경로는 2단계다: `.github/workflows/release.yml` (Stage 1 — publish) 이후
`.github/workflows/release-finalize.yml` (Stage 2 — provenance 기반 tag·Release).
이 문서는 수동 fallback 절차와, 워크플로가 대신할 수 없는 인수 확인의 기록이다.

## 이 릴리스가 싣는 것

사용자가 아무것도 켜지 않아도 ASC 가 붙은 workspace 를 계속 관측한다. 그 한 문장을
성립시키는 데 필요한 여섯 갈래가 함께 들어간다.

- **linked worktree continuity** — 같은 Git repository 의 다른 checkout 이 자동으로 같은
  논리 workspace 로 풀린다. 근거는 remote 이름이 아니라 로컬 구조이므로, 같은 remote 의
  독립 clone 은 절대 이어붙지 않는다.
- **background runtime** — workspace lease · heartbeat · `runtime stop` · 상태 표면.
  `start --detach` 는 개발·복구용으로 남는다.
- **Host Auto-Front Binding** — 지원 Host 세션이 열리면 그 자리의 기존 상태가 복원된다.
  아직 등록되지 않은 worktree 에서 Host 를 **처음** 여는 경우까지 포함하며, 그 앞에
  ASC 명령을 요구하지 않는다. 세션을 만들어 내지 않는다.
- **multi-binding observation** — code binding 과 work binding 을 함께 선언하면 채널이
  둘 다 산다. Monitor Core 에 provider 분기는 없다.
- **JAM 계약 정합** — 준비 판정을 JAM 자신의 진단에서 읽고, 고칠 수 있는 것은 JAM 의
  공식 setup 으로 고친다. 자격은 끝까지 사람 몫이다.
- **user-scope persistent singleton** — 기계당 하나의 OS 등록이 아는 workspace 전부를
  돌본다. workspace 마다 서비스를 만들지 않는다.

## Gate (publish 전 — 워크플로가 재실행하는 것과 동일)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check
[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize (tag·Release 는 Stage 2 가 만든다)
```

## Published acceptance (게시본으로만 — source checkout 금지)

```text
[ ] npx --yes @asc-agent/bootstrap@0.4.0 setup apply --json   (격리 HOME)
[ ] asc version → 0.4.0
[ ] asc runtime service status → 등록 상태를 답한다
[ ] asc runtime service install → 등록, 재실행 시 변경 0 (멱등)
[ ] OS 가 회차를 실행하고 정상 종료한다
[ ] asc runtime list → 기계 전체 workspace 를 한 화면에
[ ] 미등록 linked worktree 에서 Host hook 만으로 복원 + locator 자동 등록
[ ] 같은 remote 독립 clone → 이어붙지 않는다
[ ] code + work binding 동시 선언 → 채널 둘
[ ] 외부 상태 불변 반복 회차 → 새 보고서 0
[ ] Host open 만으로 세션·외부 write 0
```

## Stage 2 전 확인

```text
[ ] 위 published acceptance 전부 PASS
[ ] tag v0.4.0 미존재
[ ] docs/releases/v0.4.0.md 가 게시된 commit 에 존재
```
