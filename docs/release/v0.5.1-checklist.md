# ASC v0.5.1 — 릴리스 체크리스트 (fresh onboarding 완결)

정본 경로는 2단계다: `.github/workflows/release.yml` (Stage 1 — publish) 이후
`.github/workflows/release-finalize.yml` (Stage 2 — provenance 기반 tag·Release).

## 이 릴리스가 싣는 것

0.5.0 fresh 설치 실측에서 잡힌 결함 전부.

- **F1** 등록물이 npx 캐시를 가리켰다 → 임시 경로 거부 · 전역 설치본 우선 · Node 실재·>=24·비임시
- **F2** 수동 보수 4회(adopt·identity·bindings·re-lock) → 한 번의 apply 로 READY
- **F3** 등록이 붙이기보다 먼저 실행 → 순서 고정, 사람이 멈추는 계획에선 등록 0
- **F5** canonical 갈래가 비어 판정이 전부 "확인 못 함" → remote 기본 branch 자동 선언 + 새 gate
- **F6** "ASC 적용해" 를 사람이 말해야 했다 → 변경 도구가 같은 guard 를 지난다
- **F7** work binding 이 monitoring 에만 닿았다 → capability 모양으로 작업 항목 통로를 가른다

## Gate (publish 전 — 워크플로가 재실행하는 것과 동일)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check
[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize (tag·Release 는 Stage 2 가 만든다)
```

## Published acceptance (게시본으로만 — source checkout 금지)

```text
[ ] 빈 prefix 에 npx --yes @asc-agent/bootstrap@0.5.1 setup apply --json (격리 HOME, 실 저장소)
[ ] 한 번에 READY — adopt·attach·identity·bindings·canonical, remaining []
[ ] which asc 가 dev dist 를 가리키지 않는다
[ ] asc --version → 0.5.1
[ ] 등록물이 npx 캐시를 가리키지 않는다
[ ] npx 캐시를 지운 뒤에도 등록물·회차가 산다
[ ] manual tick 없이 launchd 회차가 두 채널을 연다
[ ] proceed --work <실 KEY> → WORK_STATE (JAM live + canonical)
[ ] 새 세션에서 attachment 복원
```
