# ASC v0.5.3 — 릴리스 체크리스트 (첫 설치가 등록까지)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

0.5.2 clean-room 실측에서 잡힌 결함 하나와, 그 수정이 만든 회귀 하나.

- 첫 설치가 기계 등록까지 같은 회차에서 간다 (등록 후보는 전역 설치본, 또는 이번에 놓을 것)
- 검사가 이 기계에 등록을 남기지 않는다 — 실제로 남긴 job 하나를 제거했고 회귀로 고정했다

## Gate (publish 전)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check
[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize
```

## Published acceptance (게시본으로만)

```text
[ ] 정리된 상태에서 npx --yes @asc-agent/bootstrap@0.5.3 setup apply --json
[ ] 전역 asc 설치 · asc --version → 0.5.3
[ ] 같은 회차에서 등록물 생성 · 경로가 npx 캐시도 임시 자리도 아니다
[ ] npx 캐시를 지운 뒤에도 등록물·회차가 산다
[ ] manual tick 없이 launchd 회차가 두 채널을 연다
[ ] proceed --work <실 KEY> → WORK_STATE
[ ] 새 세션에서 attachment 복원
```
