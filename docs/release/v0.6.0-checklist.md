# ASC v0.6.0 — 릴리스 체크리스트 (`asc update`)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

`asc update` 하나. 0.5.x 를 다섯 번 갈아 끼우면서 사람이 매번 손으로 한 것 — 구본 삭제,
npx 캐시 정리, 등록물 삭제, `setup apply` 재실행 — 을 공식 명령 하나로 대체한다.
그 중 `setup` 재실행이 특히 나빴다: profile·binding·정본을 **다시 추론**하는 경로다.
업데이트 경로는 그 함수들을 부르지 않으며, 회귀 검사가 그것을 지킨다.

## Gate (publish 전)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check
[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize
```

## Published acceptance (게시본으로만)

```text
[ ] 0.5.4 로 되돌린 실기계에서 asc update check --json → UPDATE_AVAILABLE (0.5.4 → 0.6.0)
[ ] asc update → install → verify → host → service → health, 되묻기 0회
[ ] asc --version 0.6.0 · 등록물 경로가 전역 설치본 · 경로에 npx 캐시 0
[ ] protected state 변경 0 (update 출력의 `state: unchanged`)
[ ] setup 재실행 0 (setup apply 가 한 번도 불리지 않는다)
[ ] host integration CURRENT · persistent service CURRENT
[ ] manual tick 없이 launchd 회차가 계속 돈다
[ ] registry 조회 불능 → UNKNOWN (CURRENT 아님)
[ ] 없는 버전 강제 → 설치 실패 후 기존 버전 복구 확인
```
