# ASC v0.6.1 — 릴리스 체크리스트 (판번호 이동은 설정 어긋남이 아니다)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

0.6.0 published acceptance 에서 잡힌 결함 하나. `asc update` 는 `setup` 을 재실행하지
않는 첫 경로였고, 그래서 `setup` 이 부수적으로 하던 재고정이 사라졌다. 그 결과 판번호가
움직였다는 이유만으로 이 machine 의 workspace 세 개가 전부 섰다 — 둘은 `0.3.1` 이후
여러 릴리스 동안 회차를 돌지 못한 상태였다.

## Gate (publish 전)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check
[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize
```

## Published acceptance (게시본으로만)

```text
[ ] asc update 로 0.6.0 → 0.6.1
[ ] 세 workspace 모두에서 asc proceed 가 lock 때문에 멈추지 않는다
[ ] profile.lock 은 한 개도 다시 쓰이지 않았다 (해시 동일)
[ ] override 를 고치면 여전히 멈춘다
[ ] manual tick 없이 회차가 세 workspace 를 전부 돈다
```
