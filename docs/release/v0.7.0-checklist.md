# ASC v0.7.0 — 릴리스 체크리스트 (끊긴 선을 잇는다)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

사전 전수조사(asc-evidence `docs/plan/0.7.0-survey/`)가 확정한 8건. 전부 **연결·판정·표시**
문제였고 새 기능이 아니다. 새 subsystem 0 · 새 SSOT 0 · 지운 죽은 모델 1(QueueItem).

## Gate (publish 전)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check
[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize
```

## Published acceptance (게시본으로만)

```text
Gate A  asc update 로 0.6.1 → 0.7.0 · setup 재실행 0 · protected state 예상 밖 변경 0
        service CURRENT · host CURRENT · 회차 지속
Gate B  자연어 한 마디로 실제 미완료 작업 착수 — 저수준 지시 0회로 세션·bind·guard 까지
Gate C  bind → 외부 write 차단 · release → RELEASED · current binding 제거 ·
        같은 physical 이 두 세션을 잡지 못한다
Gate D  git commit -m "push later" PASS · git fetch PASS · git push BLOCK · glab mr create BLOCK
Gate E  기존 파일이 있고 이번 요구 delta 가 없는 작업 → ACTIONABLE
        인수 대기 작업에 "tracker 정리만 하라" 를 권하지 않는다
Gate F  "게시해" 한 번 → 세션 근거 Grant → 실행 → read-back. 지어낸 REQ 0
Gate G  done 의 next·verified·done·unresolved 가 collect 화면과 archive 에서 같다
Gate H  회차 실패를 주입하면 attached 가 healthy 로 보이지 않는다 ·
        사람 책임 설정을 자동 수정하지 않는다
```
