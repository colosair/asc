# ASC v0.8.0 — 릴리스 체크리스트 (세 축을 가른다)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

새 capability 를 늘리지 않는다. 이미 있던 것을 세 축으로 가르고, 사람이 마주하는 표면을
그 축에 맞춰 다시 세운다.

```text
Agent Management   work / session / handoff      — 그대로
Decision Authority inbox / approval / grant      — 그대로
Execution Mode     MANUAL · AUTO                 — 새로 공개하는 축 하나
```

그리고 0.7.1 실측이 남긴 deadlock 을 구조적으로 없앤다: Guard 는 ASC control-plane 을
막지 않고, host 설치가 그 허용 규칙을 심고, `asc mode manual` 이 공식 출구다.

보정 라운드에서 더해진 것:

```text
기록 없음 = AUTO 아님          AUTO 는 명시 선택 + readiness PASS 로만 존재한다
readiness 9축                  control-plane·controller·binding·executor·provider·review·verify·guard·host
Remote Review                  나가기 전 읽기 검수 · 실행 직전 재검수 · 실행 뒤 되돌려 읽기
승인 기준 = commit             가지 이름이 아니라 그때의 SHA 를 못 박는다
실패 구분                      REJECTED · UNCERTAIN · NOT_VERIFIED · DRIFT
downgrade 보호                 AUTO 에서 mode manual · host uninstall · runtime use development 는 Controller 자리
active work uninstall          살아 있는 세션/결합이 있으면 거부
festa 경계                     정본 branch 는 쓰기 금지 목록이 아니다 — 프로젝트 정책은 프로젝트의 것
```

## Gate (publish 전)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check
[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize
```

## Published acceptance (게시본으로만 · 새 physical session 에서)

```text
[ ] Gate A  asc status · jam status 가 새 세션에서 답한다
[ ] Gate B  asc mode manual → 실제 작업 1건 · raw 읽기 PASS · ASC Guard hard-block 0
[ ] Gate C  control-plane 이 막힌 fixture 에서 asc mode auto 가 거부하고 MANUAL 이 유지된다
[ ] Gate D  전 축 READY 인 자리에서 asc mode auto 가 선다
[ ] Gate E  같은 결정이 MANUAL 과 AUTO 에서 똑같이 사람에게 올라간다
[ ] Gate F  asc work publish 로 Session → Grant → GitLab → read-back → audit 완주
[ ] Gate G  asc work finish 한 명령으로 handoff·release·collect·archive 보존
[ ] Gate H  host 설치물을 stale 로 만든 뒤 asc refresh 만으로 복구 (setup 재실행 0)
[ ] Gate I  다음 후보가 나오면 asc update → 새 build 가 refresh → probe INSTALLED_CURRENT
[ ] Gate J  격리 환경에서 asc uninstall → integration 없음 · ~/.asc 그대로
[ ] Gate K  MANUAL 에서 실제 part branch push 1건 — Guard hard block 0 · 조언 1줄
[ ] Gate L  AUTO 에서 같은 작업을 asc work publish 로 — 검수·Grant·실행·되돌려 읽기 완주
[ ] Gate M  festa-* 스킬과 함께 1회전 — 정책은 그쪽이 정하고 ASC 가 실행·검수만 한다
```
