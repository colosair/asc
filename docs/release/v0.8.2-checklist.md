# ASC v0.8.2 — 릴리스 체크리스트 (patch · Windows 실행 경로와 결합 해제)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

capability 를 늘리지 않는다. 두 갈래를 고친다.

```text
#65  runExternal 하나로 shim 해석 + windowsHide 통합
     JAM doctor·probe·heal 이 serve 와 같은 해석을 쓴다 (Windows 에서 spawn ENOENT 였다)
     자식 프로세스의 콘솔 창이 사라진다
     schtasks status 가 /Query /XML 로 간격까지 비교한다 (#62)
#66  work finish 가 physical binding 을 놓는다
     terminal 세션이 Run 을 쥔 것을 status 가 이름과 명령으로 드러낸다 (#63)
```

surface 변경 없음 · state schema 변경 없음 · `~/.asc` 무변경.


## Published acceptance (게시본으로만)

0.8.1 의 W-1~W-6 은 이 patch 가 건드리지 않은 축이라 되풀이하지 않는다. 이번이 확인해야
하는 것은 **고친 둘이 게시본에서 실제로 동작하는가**이고, 그 확인은 Windows 실기계에서만
뜻이 있다.

```text
[ ] X-1  asc work finish 뒤 physical binding 이 놓인다
         → 같은 Run 으로 다음 세션 bind 가 RUNTIME_CONFLICT 없이 선다
         → runtime-binding-<S-ID>.json 이 남지 않는다
[ ] X-2  terminal 세션이 Run 을 쥔 것을 status 가 드러낸다
         → Degraded 절에 세션 id 와 release 명령이 함께 나온다
[ ] X-3  이미 쌓인 잔존 결합이 그대로 뜨고, 아무것도 지워지지 않는다
         → 이 기계의 8월 31일 여섯을 산 표본으로 쓴다
         → status 실행 전후로 runtime-binding-*.json 개수가 같다
[ ] X-4  JAM 세 경로가 Windows 에서 AVAILABLE 이다
         → doctor · probe · heal 각각. 0.8.1 은 "spawn npx ENOENT" 였다
[ ] X-5  schtasks 간격 변경이 STALE 로 잡힌다
         → 60분 등록 · 5분 기대 → STALE / 60분 등록 · 60분 기대(PT1H) → CURRENT
[ ] X-6  0.8.1 → 0.8.2 를 asc update 로 올라올 수 있다
         → 0.8.1 에는 D4 가 고쳐져 있으므로 이번엔 되어야 한다. 0.8.1 W-6 의 짝이고,
           안 되면 그것은 새 결함이다
[ ] X-7  자식 프로세스의 콘솔 창이 실제로 안 뜬다
         → glab·npx 를 부르는 회차를 한 번 돌려 눈으로 본다
         → 예약 작업 자체의 창은 여전히 뜬다 — 이 항목은 자식 프로세스 쪽만이다
```

X-7 은 **사람 눈이 필요한 유일한 항목**이다. 유닛으로 못 잡는다.

X-3 이 이번 회차의 핵심이다. **수정이 무엇을 하지 않는가**를 재는 항목이고, 그 표본은
한 번 쓰면 사라진다 — 인수 전에 잔존 결합을 정리하지 않는다.

X-1 은 기계 상태를 바꾼다. 실행 전에 같은 기계에서 도는 다른 세션에 알린다.

**#67(개발 빌드 식별)은 이 회차에서 확인할 수 없다.** 지금 재현되는 이유는 다른 세션의
개발 빌드 소스가 게시본보다 앞서 있기 때문이고, 0.8.2 가 나가면 그 둘이 같아져 STALE 이
나오지 않는다. 다음 수정 커밋이 들어가야 다시 재현된다 — 인수 항목으로 세우지 않는다.

macOS·Linux 실기계 등록은 이번에도 못 밟는다 — Mac 이 없다. 노트 Known limitations 에
**두 릴리스째**로 명시했다.

## 릴리스 완료 판정 (근거 없이 0 으로 적지 않는다)

```text
[ ] BINDING_LEFT_AFTER_FINISH = 0
[ ] HELD_RUN_INVISIBLE_IN_STATUS = 0
[ ] SILENT_CLEANUP_OF_USER_STATE = 0      ← 드러내되 지우지 않는다
[ ] EXTERNAL_COMMAND_BYPASSING_runExternal = 0
[ ] CONSOLE_WINDOW_FROM_CHILD_PROCESS = 0
[ ] SURFACE_CHANGE = 0
[ ] STATE_SCHEMA_CHANGE = 0
```

## 이 회차가 안고 가는 것

```text
예약 작업 자체의 콘솔 창    /RU /NP 는 관리자 권한 필요, Hidden 은 UI 목록 플래그 —
                            둘 다 실측으로 막혔다. wscript 래퍼는 ASC_HOME 에 파일을
                            더하는 설계 결정이라 별건이다
macOS·Linux 실기계          두 릴리스째 미실행
개발 빌드 식별 불가          --version 도 runtime status 도 게시본과 구분되지 않는다.
                            개발 빌드가 대는 Next: asc refresh 를 그대로 치면 미게시
                            코드가 host 통합에 들어간다
```

셋 다 노트 Known limitations 에 적었다. 적었다는 것이 해결했다는 뜻이 아니다.
