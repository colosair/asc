# ASC v0.8.3 — 릴리스 체크리스트 (patch · AUTO dead-end)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

capability 를 늘리지 않는다. 세 축이 어긋나 생긴 dead-end 하나를 닫는다.

```text
실사용 실패   AUTO → guard 가 raw push 차단 → managed GitLab git.push executor 미확보
              → 정상 출구 없음 → 사용자가 직접 mode manual → raw push
```

```text
#70  GitLab 이 executor 슬롯에 닿는 capability 를 선언한다
     막히는데 관리 경로가 없는 행위를 status·mode 가 이름 댄다
     거부가 어느 결합이 무엇을 싣는지 말한다
     skill 의 무조건 external-write 금지를 AUTO 조건부로 (MANUAL 계약과 어긋났다)
     mode 판정 두 구현의 다섯 자리 일치를 테스트로 고정
```

surface 변경 없음 · state schema 변경 없음 · `~/.asc` 무변경.


## Published acceptance (게시본으로만 · 실제 GitLab remote)

0.8.1 의 W-·0.8.2 의 X- 는 이 patch 가 건드리지 않은 축이라 되풀이하지 않는다.

```text
[ ] A  MANUAL raw push
       mode manual --as <actor> → chosen: true
       실제 git push (--dry-run) 이 host → hook → git 을 관통한다
       ASC hard-block 0 · skill 도 막지 않는다
[ ] B  AUTO raw bypass
       결합 없는 자리와 결합된 자리 둘 다 exit 2
       결합된 자리의 배너는 asc work publish 를 대고 mode manual 을 대지 않는다
[ ] C  AUTO managed GitLab push
       mode AUTO 유지 → work publish → Remote review READY(mutation 0)
       → EXECUTED → git ls-remote 로 SHA 대조
       중간 mode 변경 0 · 사용자 raw push 0 · MANUAL 안내 0 · bypass 0
[ ] D  관리 경로 없는 action
       거부가 어느 결합이 무엇을 싣는지 말한다
       성공 가장 0 · 성공 기록 0 · MANUAL 강요 0
       존재하지 않는 capability 명칭을 지어내지 않는다
[ ] E  dead-end 목록
       status·mode 가 막히지만 못 나가는 행위를 이름 댄다
```

C 가 이 회차의 본체다. **단위 테스트에서 `supports('git.push') === true` 를 확인하고
끝내지 않는다** — 실제 remote 까지 관통해야 한다.

A 는 `--dry-run` 으로 원격을 바꾸지 않고 전 구간을 탄다. 실제 push 가 필요하면 일회성
브랜치에서만 한다.

## 릴리스 완료 판정 (근거 없이 0 으로 적지 않는다)

```text
[ ] STATE_SCHEMA_CHANGE = 0
```

## 이 회차가 안고 가는 것

```text
guard push 패턴이 중간 단어를 건너뛴다   커밋 메시지에 그 낱말이 들어가면 명령으로 읽힌다.
                                        이번 릴리스를 준비하다 밟았고 고치지 않았다
개발 빌드 식별 불가                      0.8.2 와 같다. 이번에도 계속 밟았다 —
                                        AUTO 를 켜는 데 게시본 CLI 를 써야 했다
macOS·Linux 실기계                       세 릴리스째 미실행
예약 작업 자체의 콘솔 창                  0.8.2 가 고친 것은 자식 프로세스 쪽뿐이다
```

넷 다 노트 Known limitations 에 적었다. 적었다는 것이 해결했다는 뜻이 아니다.
