# ASC v0.8.4 — 릴리스 체크리스트 (patch · lifecycle reconnect)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

한 실제 workspace 전수조사에서 나온 결함 열 건. 붙어 있고 돌고 있는데 쓰이지 않던 이유다.

```text
실사용 실패   AUTO 12시간 · 프로젝트 push 0건
              그 구간에 관리 경로를 탄 write 1건 — ASC 자기 인수 시험
              Jira 작업 4건 · ASC work 0건 · managed write 0건 · coordination 0건
              inbox 는 18시간 동안 원본을 한 번도 다시 읽지 않았다
```

```text
#72  inbox 가 원본 현재 상태와 맞는다 (OBSOLETE — 처분이 아니라 관측)
     monitor 가 "마지막 시도 성공" 과 "지금 최신" 을 가른다
     Execution Mode 를 Run 이 답한다 — 한 Run 의 결정이 남의 Run 을 바꾸지 않는다
     bind 가 guard 와 같은 신원을 쓴다
     같은 결정 주체를 두 번 묻지 않는다
     발견됐는데 선언되지 않은 결합을 이름 대고 붙이는 줄을 준다
     외부 대기를 계약 없이 기록한다 (coordination attach)
     dead-end 를 이 workspace 가 쓰는 것으로 좁힌다
     결정권 미선언을 화면이 말한다
     skill 이 남의 물음을 가로채지 않는다
     조립이 쓰지 않는 도구에 외부 프로세스를 띄우지 않는다 (18.5s → 0.3s)
```

state schema 변경 있음 — 아래 참조. `~/.asc` 는 업그레이드만으로 바뀌지 않는다.

## Gate (publish 전)

```text
[ ] npm run typecheck / build / test
[ ] npm run release:check          — 0.8.4 명명·note 섹션·버전 리터럴
[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check
[ ] 3-OS CI green on main
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize
```

## Published acceptance (게시본으로만 · 실제 workspace)

0.8.1 의 W-·0.8.2 의 X-·0.8.3 의 A~E 는 이 patch 가 건드리지 않은 축이라 되풀이하지 않는다.
단 **C(관리 경로 관통)는 다시 돈다** — 조립을 손댔기 때문이다.

```text
[ ] L-1  work 진입
         asc work start <WORK-KEY> 가 UNDECIDABLE 이 아니라 판정과 근거를 낸다
         선언이 없으면 후보와 붙이는 줄을 이름 댄다
[ ] L-2  결합 가시성
         발견됐는데 선언되지 않은 것이 status 에 뜬다. 못 쓰는 것도 이유와 함께 뜬다
[ ] L-3  결정권
         ownership 미선언이 화면에 뜨고 채울 자리를 댄다
[ ] L-4  외부 대기
         query open → coordination attach → asc coordination 에 WAITING_EXTERNAL
         계약 0 · 밖에 새로 만든 것 0 · 되읽기로 실재 확인
[ ] L-5  Run scope
         한 Run 을 AUTO 로 올려도 같은 workspace 의 다른 Run 은 그대로다
         guard 가 두 Run 에 서로 다른 답을 준다 (같은 명령·같은 시각)
[ ] L-6  관리 경로 (0.8.3 C 재시행)
         AUTO 유지 → work publish → review READY → EXECUTED → remote SHA 대조
         중간 mode 변경 0 · raw write 0 · bypass 0
[ ] L-7  inbox 대조
         원본이 닫힌 요청만 OBSOLETE 로 가고 decision 은 비어 있다
         열린 것은 그대로 선다 · 못 읽으면 못 읽었다고 말한다
[ ] L-8  monitor 최신성
         오래됐으면 STALE/NOT_RUNNING 이라 말한다. "정상" 하나로 끝내지 않는다
[ ] L-9  bind 신원
         라벨은 거부되고 쓸 값을 알려 준다 · 인자 없으면 자기 Run 을 관측한다
[ ] L-10 lifecycle 종결
         progress → work finish → Run 반납 · 열린 query 가 "판단 필요" 로 뜬다
[ ] L-11 festa-* 없이 위 전부가 성립한다
[ ] L-12 조립 비용
         이 도구를 쓰지 않는 저장소에서 명령이 1초 안에 끝난다
```

L-5 와 L-7 이 이 회차의 본체다. **다른 Run 이 실제로 돌고 있는 동안** 재야 한다 —
혼자 있는 기계에서는 재현되지 않는 결함이었다.

## 릴리스 완료 판정 (근거 없이 0 으로 적지 않는다)

```text
[ ] STALE_APPROVAL_AFTER_ORIGIN_SETTLED = 0
[ ] OBSOLETE_CARRYING_A_DECISION = 0
[ ] MONITOR_SAYS_NORMAL_WHILE_STALE = 0
[ ] ONE_RUN_CHANGED_ANOTHER_RUNS_ENFORCEMENT = 0
[ ] BINDING_INVISIBLE_TO_GUARD = 0
[ ] DISCOVERED_BINDING_UNMENTIONED = 0
[ ] EXPECTATION_REQUIRING_A_GRANT_TO_RECORD = 0
[ ] DEAD_END_FOR_A_PROVIDER_THIS_WORKSPACE_DOES_NOT_DECLARE = 0
```

## 이 회차가 안고 가는 것

```text
guard 의 범위가 세션 cwd 다               다른 저장소로 나가는 쓰기를 이 workspace 기준으로 막는다.
                                          이번에 밟았고 고치지 않았다
개발 빌드 식별 불가                        0.8.2·0.8.3 과 같다. runtime use development 로 우회했다
macOS·Linux 실기계                        네 릴리스째 미실행
예약 작업 자체의 콘솔 창                   그대로
```

넷 다 노트 Known limitations 에 적었다. 적었다는 것이 해결했다는 뜻이 아니다.
