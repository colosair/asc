# ASC v0.8.5 — 릴리스 체크리스트 (patch · inbox candidate discovery + Windows runtime)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

실기계에서 답이 왔는데 판단 대기함에 오르지 않은 스레드 세 건. 그 원인과, 그 길을
실제로 걷게 만들면서 드러난 것들.

```text
실사용 실패   알림 없는 답 3건 · inbox 후보 0건
              replyToMe 는 0.7 부터 있었고 production 호출자가 0이었다
              상시 등록은 회차마다 콘솔 창이 떠서 사람이 꺼 두었다
```

```text
#80  스레드에서 누구 차례인지 읽는다 (change 통로가 없어도)
     방향은 구조에서만 — ownership·authority 를 입력으로 받지 않는다
     소비 대조는 ASC 가 가진 원장만 보고, 어디를 봤는지 이름을 댄다
     스레드 조회에 예산이 있고, 넘긴 것은 세 곳 어디에서도 "본 것" 이 되지 않는다
     목록이 이미 준 사실을 단건 조회로 다시 묻지 않는다
     내가 열었거나 배정된 것을 먼저 읽는다 (거르지는 않는다)
     예약 회차가 창을 띄우지 않고, 출력이 로그로 간다
     guard 가 어느 workspace 기준으로 막았는지 말하고, 못 실어 나를 경로를 내밀지 않는다
     멈춘 채 잊힌 세션을 이름 대고 닫지는 않는다
     없는 세션에 결합을 만들지 않는다
     profile.lock 판번호 경고가 상태 화면 한 곳으로
```

state schema 변경 있음 (전부 optional 추가) — 노트 Compatibility 참조.
**Windows 등록은 이 판에서 교체된다** — 이전 등록은 STALE 로 읽힌다.

## Gate (publish 전)

```text
[ ] npm run typecheck / build / test

[ ] npm run pack:all && npm run smoke
[ ] npm run presentation:check
[ ] 3-OS CI green on main
```

## 수동 fallback (워크플로 불능 시에만)

```text
[ ] publish @asc-agent/runtime   → verify on the registry
[ ] publish @asc-agent/bootstrap → verify   (bootstrap 이 runtime 을 exact 로 가리킨다 — 순서 고정)
[ ] published smoke → 인수 → finalize
```

## Published acceptance (게시본으로만 · 실제 workspace)

0.8.4 의 L-1~L-12 중 이 patch 가 건드리지 않은 축은 되풀이하지 않는다.
**L-6(관리 경로 관통)과 L-11(festa-* 없이)은 다시 돈다** — 조립을 손댔기 때문이다.

```text
[ ] M-1  후보 발견
         내가 묻고 상대가 답한 스레드가 알림 없이도 판단 대기함에 오른다
         source.direction = INBOUND · lastOtherAt 이 실제 답변 시각
[ ] M-2  방향과 소유가 갈린다
         내가 마지막으로 말한 스레드는 후보가 아니고, 기다림으로 남는다
         내가 말한 적 없는 스레드는 UNKNOWN 으로 남고 내 차례가 되지 않는다
[ ] M-3  소비 대조
         각 건이 "무엇을 확인했는지" 를 이름 댄다
         확인 자체가 안 된 건은 "가리지 못했다" 로 말한다 — "답이 왔다" 로 접지 않는다
[ ] M-4  예산과 미룸
         예산을 넘긴 건수가 화면에 뜬다 ("N not yet read")
         다음 회차가 그것을 실제로 연다 — coverage 크기가 아니라 조회 자체로 확인
[ ] M-5  비용
         같은 workspace 에서 0.8.4 대비 회차당 API 호출·소요를 잰다
         정상 상태 회차가 한 자릿수 호출로 끝난다
[ ] M-6  Windows 상시 등록 (실기계 · CI green 으로 대체 금지)
         install → schtasks /Run → 새로 보이는 창 0
         service.log 에 회차 출력이 남는다
         asc monitor status 가 HEALTHY 에 닿는다
         이전 판 등록이 STALE 로 읽혀 교체된다
[ ] M-7  guard 범위 문구
         cwd=A 에서 B 로 나가는 쓰기가 막히고, A 의 관리 경로를 해결책으로 내밀지 않는다
         대상을 모를 때도 막는다 (fail-open 0)
[ ] M-8  멈춘 세션
         하루 넘게 조용한 PAUSED 세션이 근거와 두 명령과 함께 뜬다
         자동으로 닫히지 않는다
[ ] M-9  bind 거절
         없는 논리 세션에 bind 가 거절되고 결합 파일도 실행 증거도 남지 않는다
         release 는 그대로 동작한다
[ ] M-10 lock 잡음
         일반 명령에서 profile.lock 판번호 줄이 나오지 않는다
         asc status 의 degraded 목록에 한 줄로 있다
[ ] M-11 관리 경로 (0.8.4 L-6 재시행)
         AUTO 유지 → work publish → review READY → EXECUTED → remote SHA 대조
[ ] M-12 festa-* 없이 위 전부가 성립한다
```

M-4 와 M-6 이 이 회차의 본체다. M-6 은 **실기계에서만** 성립한다 — CI 는 창이 뜨는지
말해 주지 못한다.

## 이 회차가 안고 가는 것

```text
guard 의 범위가 세션 cwd 다               문구만 고쳤다. 범위는 그대로다 — 두 회차째다
ASC 밖에서 소비된 답                       한 번은 뜬다. 화면이 무엇을 봤는지 이름을 댄다
댓글로만 참여한 스레드                     거르지 않지만 뒷줄이다. 목록이 발언자를 주지 않는다
미룬 항목의 실기계 재현                    fixture 로 고정했고 실기계 cold 재현은 못 했다
죽은 workspace 의 회차 실패                로그를 켜서 드러났다. 7/8 이 exit 2 다. 고치지 않았다
macOS·Linux 실기계                        다섯 릴리스째 미실행
```

여섯 다 노트 Known limitations 에 적었다. 적었다는 것이 해결했다는 뜻이 아니다.
