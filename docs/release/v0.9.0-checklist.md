# ASC v0.9.0 — 릴리스 체크리스트 (minor · guard retirement + work-start binding + self-hosted GitLab)

정본 경로는 2단계다: `release.yml` (publish) 이후 `release-finalize.yml` (tag·Release).

## 이 릴리스가 싣는 것

실기계 AUTO 세션에서 `git push` 와 `glab api GET` 이 guard 에 막힌 뒤 갈 곳이 없었다. guard 는
RuntimeBinding 파일 하나로 판정했고, `work start` 는 binding 을 만들지 않았으며, publish 통로는
자체 호스팅 GitLab 을 gitlab.com 으로 조립하고 있었다.

```text
실사용 실패   AUTO 에서 raw push 차단 → 안내된 세 명령 어느 것도 통로가 아니었다
              glab api GET 도 같은 패턴에 막혔고 bind 해도 풀리지 않았다
              F6(Edit/Write) 은 install marker 중복으로 한 번도 등록된 적이 없었다
```

```text
#82  PreToolUse guard 와 파생 구조(classifier · F6 · heartbeat · probe · worker-settings · dead-end) 폐기
     install/refresh/update 가 0.8.x guard 설치물을 소유권 증명으로만 걷는다 (사용자 수정본은 보고·보존)
     Execution Mode = 승인된 행위를 누가 수행하는가. readiness 는 executor · control-plane 둘
     asc work start 가 이 Run 을 세션에 묶는다 — CONFLICT 는 exit 1, 전이는 유지, 소유자 무변경
     --physical 은 소유권을 소비하는 명령에서만 이 Run 으로 채워진다 (명시값 우선)
     Executor 가 remote freeze 를 CLAIM 전에 읽는다 (FROZEN · grant READY 유지)
     GitLab: plan 캐시가 adapter 를 함께 들고, glab 에 --hostname, remote 는 발견된 이름으로
     skill 이 AUTO/MANUAL 계약을 각각 적고 guard 를 글로 재생성하지 않는다
     threat model: ASC 는 관리 mutation 만 보장하고 셸을 격리한다고 주장하지 않는다
```

state schema 변경 없음. **host settings.json 은 upgrade 시 바뀐다** — ASC 소유 PreToolUse 항목이 걷힌다.

## Published acceptance (게시본으로만 · 실제 자체 호스팅 workspace)

대상: 자체 호스팅 GitLab 의 실 팀 프로젝트(이름은 저장소에 적지 않는다), macOS, Claude Code Run 안에서.
project 브랜치(main/develop/front …)는 건드리지 않는다. throwaway 브랜치 하나만 원격에 오르고 내려간다.

```text
[ ] A-0  사전 기록 — originalBranch · originalHead · originalStatus · identities.json 원본(sha256)
         acceptance 를 위해 identities.json 에 local:colosair 를 더한다 (종료 후 원복)
[ ] A-1  0.8.5 → 0.9.0 update / migration
         asc --version == 0.9.0 · settings.json 에 PreToolUse asc 항목 0 · guard-hook.mjs 제거
         SessionStart/front 항목 정상 · Bash(asc:*) allow 유지 · verifyInstall CURRENT
[ ] A-2  자체 호스팅 GitLab execution binding
         asc status --json: external.write.id == gitlab · actions 에 git.push · endpoint host 가 자체 호스팅 주소
[ ] A-3  Session contract / Controller issue boundary
         work start → PROPOSE_CONTRACT(forController) · 사람이 session issue
[ ] A-4  work start → current Run auto-bind
         exit 0 · kind STARTED · binding CLAIMED · physical == CLAUDE_CODE_SESSION_ID
[ ] A-4a 재실행 → ALREADY · asc status "held by this Run"
[ ] A-4b Claude Run 밖 → NO_RUN · exit 0 · 결합 파일 없음
[ ] A-4c 경쟁 owner → 같은 Run 에서 두 번째 세션 work start → exit 1 · CONFLICT · 두 번째 세션 STARTED 유지 · 첫 세션 소유자 무변경
[ ] A-5  guard 없는 일반 read — glab api --hostname <host> projects/… 가 200
[ ] A-6  throwaway 로컬 브랜치 + fixture commit
[ ] A-7  managed git.push review — work publish --review → READY · remote host 가 자체 호스팅 주소
[ ] A-8  사용자 최종 확인 후 Grant/Executor — work publish → G-… READY → EXECUTED
[ ] A-9  remote SHA read-back — git ls-remote origin refs/heads/<throwaway> == git rev-parse HEAD
[ ] A-10 execution/audit evidence — session audit: 'work start' 실행 증거 + grant EXECUTED + remote sha
[ ] A-11 work finish (--physical 없이) → ownership released · 결합 파일 삭제
```

```text
[ ] A-12 Release operator fixture cleanup (제품 인수와 별도 보고 · MANUAL 작업 · 새 capability 없음)
         원격 throwaway 브랜치 삭제 → git ls-remote 빈 출력 확인 → 로컬 브랜치 삭제
         → originalBranch 로 복귀 · HEAD == originalHead → identities.json 원복(sha256 대조)
         → git status --porcelain == originalStatus
```

A-1·A-4·A-4c·A-8 이 이 회차의 본체다. A-1 은 **실제 0.8.5 설치본 위에서만** 성립한다 — fixture 는
CI 가 돌렸고, 실기계는 여기서 돈다.

## 이 회차가 안고 가는 것

```text
셸은 ASC 의 경계가 아니다                  0.8.x 도 아니었다. 이제 그렇게 적혀 있다
freeze 가 셸 읽기를 막지 않는다            monitor 와 Executor 만 얼린다
renderProgress 의 liveness 입력            생산자가 사라졌다. Core 타입이라 후속에서 정리
policy.evaluate 호출자 0                   이전과 같다. 후속
OperatorDeps.guard 명칭                    bootstrap 검증이다. 이름만 충돌. 후속
identityOf 가 path-only                    같은 path 다른 host 는 review 가 못 가른다
Windows 실기계                             이번 회차는 CI 만
```

일곱 다 노트 Known limitations 에 적었다. 적었다는 것이 해결했다는 뜻이 아니다.
