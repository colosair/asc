ASC 0.10.2 fixes the one thing the published acceptance of 0.10.1 found, again on the
non-delegated issuance path that 0.10.0 introduced. Nothing else moves.

## What changed

**A new proposal never takes a closed proposal's id.** `asc work start` derives the next
session id from the ids already used, and that list counted sessions but not proposals. On
a workspace where a proposal had been rejected earlier the same day, the next derived
draft carried that proposal's id; the ledger refused the duplicate — correctly — but the
command still printed that the proposal was saved, and `asc work issue` then found
nothing to issue. The used-id list now includes every proposal the ledger knows, closed
ones included, and when a proposal cannot be saved the outcome carries only the advanced
handout and says so.

## Compatibility

- Node 24 or newer, unchanged.
- No schema, identity, Profile or CLI-surface change.
- Session ids derived by `work start` may skip a number that a closed proposal holds.

## Verified

- Three-OS CI: typecheck, build, the full suite (1731 tests, 1730 pass / 0 fail / 1
  skipped), release checks, packaging, packaged smoke.
- The ledger's id list includes closed proposals; a duplicate id leaves the outcome
  without a `proposal` and does not overwrite the closed one.
- Published acceptance on the maintainer's macOS host re-runs the non-delegated path end
  to end (`work start` → proposal → `work issue` → `work start` claims) and is recorded in
  `docs/release/v0.10.2-checklist.md` before the tag.

## Known limitations

Unchanged from 0.10.0.
