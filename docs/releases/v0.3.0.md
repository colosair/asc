ASC 0.3.0 turns a work request into a session: `asc proceed --work <KEY>` reads the
actual state of the work, derives a contract draft, and issues it only inside a
delegated scope. It also makes the persistent installation a verified path of its
own, so `npm install -g` is a tested tier rather than a workaround.

## What changed

- `asc proceed --work <KEY>` — investigation → work-state judgement → contract
  derivation → issuance within delegation, with the new `WORK_STATE` outcome.
- Judgement safety: no recommendation without an observed repository, role
  scopes are ceilings (the `**` auto-boundary path is gone), stale-tracker
  verdicts only from surviving artefact evidence.
- `asc setup identity` — approver registration, re-lock, and gate re-check in
  one command.
- Archived session ids can no longer be reused (both state stores).
- Persistent distribution made canonical: a global-install smoke, documented
  `npm install -g` pin checks, and the three-tier execution model
  (zero-install / persistent / development) documented.

## Install / Upgrade

```bash
npx --yes @asc-agent/bootstrap@0.3.0 init
```

Existing installations upgrade the runtime in place:

```bash
npm install -g @asc-agent/runtime@0.3.0
```

`ASC_HOME` state, workspaces and sessions are untouched by the upgrade.

## Agent setup

No change to the canonical entry:

```bash
npx --yes @asc-agent/bootstrap@0.3.0 setup apply --json
```

## Compatibility

- Node 24 or newer, unchanged.
- No breaking change to the JSON surface; `WORK_STATE` is a new outcome value.
