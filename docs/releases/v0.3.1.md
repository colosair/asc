ASC 0.3.1 carries the P0 fixes from a real-world misjudgement incident
(a field run on a real project): ASC could confirm work as actionable on top of stale
observations, and could underweight measured counter-evidence. Both holes are
closed, and the runtime now re-executes itself under a compatible Node instead
of prescribing one.

## What changed

- **Freshness gate** — no ACTIONABLE verdict on top of a stale observation.
- **Evidence adequacy** — `evidenceGrade`, bounded wording, and demotion when a
  measured refutation exists.
- **Content equivalence** — `git cherry`-based judgement for single-commit
  squash, rebase and cherry-pick, so "already landed" is detected as content,
  not as a SHA.
- **Node self re-exec** — when the current Node is too old, ASC finds a
  compatible runtime already on the machine and re-runs the same command under
  it, for that invocation only.
- `profile resolve` marks probe-measured values; the skill trigger covers
  status-shaped questions; the hard-coded `ASC_VERSION` is gone.

## Install / Upgrade

```bash
npx --yes @asc-agent/bootstrap@0.3.1 init
```

```bash
npm install -g @asc-agent/runtime@0.3.1
```

**Upgrade note (one-time LOCK_DRIFT):** workspaces attached by 0.3.0 or older
recorded `ascCore` as `0.2.1` (a hard-coding bug this release removes). The
first command after upgrading stops with `LOCK_DRIFT` — that is the lock
philosophy working, not a fault. Recover once:

```text
asc profile resolve --profile <id> --write
```

## Agent setup

```bash
npx --yes @asc-agent/bootstrap@0.3.1 setup apply --json
```

## Compatibility

- Node 24 or newer, unchanged.
- Existing workspaces, sessions and evidence are preserved; only the
  `profile.lock` re-lock above may be needed once.
