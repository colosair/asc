ASC 0.3.2 makes ASC actually work on Windows in the field. A fresh Windows
machine can now install, attach, probe its Claude Code host and run the full
session lifecycle with zero manual workarounds — every defect found in the
SSAFESTA Windows field verification (2026-08-31) is fixed in this release.

## What changed

- **Windows CLI resolution (P0)** — npm-installed CLIs are `.cmd` shims on
  Windows, and spawning them by bare name failed, so `asc host claude probe`
  reported a present Claude Code as *not found* and stopped the safety gate.
  `resolveExternalCommand` now runs a found `.exe` directly, extracts the JS
  entry out of an npm shim, or falls back to `cmd.exe /d /c` — the host probe
  and the JAM MCP client both use it.
- **Broken-attachment honesty** — an empty `.asc/` skeleton used to be read as
  attached, so `setup apply` answered `applied` and handed back a `proceed`
  that would fail. A broken attachment is now observed as such and the repair
  (re-attach) is listed in the plan; with no profile chosen it stops at
  selection instead of claiming success.
- **Workspace resolution** — a *different* home's `~/.asc` (recognised by its
  `workspaces/`, `profiles/`, `runtime.json` content) is no longer mistaken for
  a project-local attachment. On Windows the temp directory lives under the
  user profile, which made this misresolution routine.
- `asc --version` / `asc version` — the running version is finally queryable;
  unknown options answer as user errors instead of Node stacks.
- Clearer errors throughout: role and decision-class rejections name the valid
  choices; ownership rejections name the recovery command (`--physical
  <owner>` or the host release).
- Evidence encoding confirmed sound: capability evidence is valid UTF-8 and a
  regression test now pins the round-trip (the earlier mojibake report was a
  PowerShell 5.1 `Get-Content` read-side artefact).

## Install / Upgrade

```bash
npx --yes @asc-agent/bootstrap@0.3.2 init
```

```bash
npm install -g @asc-agent/runtime@0.3.2
```

In-place upgrade preserves workspaces, sessions, checkpoints, handoffs and
audit evidence — verified against a live operating workspace.

## Agent setup

No change to the canonical entry:

```bash
npx --yes @asc-agent/bootstrap@0.3.2 setup apply --json
```

## Compatibility

- Node 24 or newer, unchanged.
- No JSON-surface breaking change. New: `--version`, richer error texts, and a
  repair (`attach-workspace`) change appearing in plans over a broken
  attachment.

## Verified

- 1218 tests, typecheck, `release:check`, `pack:all`, tarball smoke — green on
  Windows locally and on the 3-OS CI matrix (ubuntu / macos / windows).
- Baseline comparison: the same Windows machine runs main@0.3.1's tarball
  smoke with 24 failures; 0.3.2 runs it clean.
- Published-registry fresh install on Windows: bootstrap → runtime install →
  `asc --version` = 0.3.2 → attach → `host claude probe` finds Claude Code
  2.1.246 with `external_write_guard` verified — no STOP misjudgement.
- Full session lifecycle (issue → start → bind → progress → pause → resume →
  decision → done → collect), duplicate-id refusal, and crash-rebind recovery
  (`RUNTIME_CONFLICT` → `--force`) exercised against the published package.
- In-place re-apply over an existing operating workspace: plan
  `already_configured`, workspace/profile/sessions/evidence preserved.

## Known limitations

- The release was published by the tag-triggered workflow; its registry
  verification step timed out against npm propagation lag after a successful
  publish, so the GitHub Release was created by hand. The successor pipeline
  (publish and finalize as separate dispatches, propagation-tolerant
  verification) removes both failure modes.
