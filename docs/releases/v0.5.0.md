ASC 0.5.0 adds generic external coordination as a first-class capability and closes
the persistent-runtime defects found during real-project dogfood. A dependency being
declared, that dependency reaching the person who owns it, and that person answering are
now three separate, provable facts — and the runtime that observes them keeps working when
the OS starts it rather than a shell.

## What changed

New capability — coordination

- **Asking, reaching and answering are kept apart.** A bounded query is the expectation.
  Two append-only ledgers record that it was published somewhere outside and that
  something came back. The coordination state — `UNPUBLISHED`, `WAITING_EXTERNAL`,
  `RESPONSE_RECEIVED`, `PUBLISHED` — is derived from evidence and never stored. A work
  item existing, or a comment appearing, never promotes an expectation on its own.
- **Publishing finds before it creates, and verifies before it claims.** The coordination
  surface port requires discover, create and read-back. A publish ends only as
  `ATTACH_EXISTING`, `CREATE_NEW` or `AMBIGUOUS`, and `AMBIGUOUS` never creates. A failed
  discovery is its own outcome, because "could not look" read as "not there" is what
  produces a duplicate.
- **Identity is the remote's stable id, not the URL.** Success is judged from
  `objectType` + `objectId`; the locator is for people. A lost create response leads to one
  object, not two — the next pass re-discovers instead of re-creating.
- **The public payload is a type, not a convention.** Title, body and labels are all that
  can cross the boundary; internal notes and routing have no field to travel in.
- **GitLab is the first real coordination surface.** Discovery by known identity, by a
  correlation label the adapter plants itself, and by work reference (reported as weak).
  Identity is `group/project#iid`. Core gains no provider branch and no provider name; the
  same contract runs against a fixture adapter with core unchanged.
- **`asc coordination publish` and `asc coordination observe`.** Publish takes the body
  from a file so nothing passes through shell quoting and no argument can carry an internal
  note. Observe reads replies through the channel that published, counting neither the
  system's own marks nor your own writing as an answer. An answer is recorded as arrival
  only — there is no field for what it decided.
- **The canonical baseline is read the way the profile declares it.** Sessions on a
  project whose canonical source is plain git against another host could not be issued at
  all; the baseline is now read from the checkout when the profile says `git`.

Runtime fixes

- **A service-started runtime can find its external executables.** The registration
  records only the directories where the needed executables actually are, with the system
  defaults after them — not the shell's PATH, which carries per-session noise. launchd and
  systemd receive that environment; a tool that cannot be found is reported, not dropped.
  launchd registrations also gain a log path.
- **A machine pass reports partial failure.** Every workspace still runs regardless of the
  others; the pass exits non-zero when any of them failed and names them.
- **The GitLab todo cursor is monotonic.** A high-water mark carries across pages and the
  next baseline is never earlier than the previous one. Timestamps are compared as
  instants, since the API mixes offsets.
- `state.md` renders write-boundary occupancy readably; the zero-footprint check ignores
  git's own transient lock files.

## Install / Upgrade

```bash
npx --yes @asc-agent/bootstrap@0.5.0 setup apply --json
```

Already installed:

```bash
npm install -g @asc-agent/runtime@0.5.0
```

Existing state is read as it is. Workspaces, profiles, sessions, checkpoints, handoffs,
decisions and audit records are preserved; nothing is migrated or rewritten. An existing
machine registration compares as behind the new form (it carries no environment) and
converges with one `asc runtime service install`.

## Agent setup

The canonical entry is unchanged:

```bash
npx --yes @asc-agent/bootstrap@0.5.0 setup apply --json
```

Coordination is opt-in by binding: a profile whose provider offers the
`coordination.surface` capability gets the publish and observe surfaces; a profile without
one sees that capability listed as unavailable and nothing else changes.

## Compatibility

- Node 24 or newer, unchanged.
- State schema unchanged. Two new append-only ledgers are added under the workspace; no
  migration runs and none is required.
- No command was removed. New: `asc coordination [status|publish|observe]`.
- One new provider-neutral capability, `coordination.surface`. Undeclared capabilities are
  reported as unavailable, as they always were.
- The registration file format gains environment and log entries; older registrations
  converge through the existing STALE path.
- JAM is consumed through its published packages at the version JAM reports for itself.
  ASC pins no JAM version of its own, and JAM did not change for this release.

## Verified

- Three-OS CI on every merged change: typecheck, build, full tests, release checks,
  packaging, packaged smoke.
- Coordination walked on a real project against two real threads: both attached to
  existing artefacts with zero creations; one with no reply stayed `WAITING_EXTERNAL`,
  one with two real replies from the other team became `RESPONSE_RECEIVED`, with the
  thread's eight system notes and the author's own comments excluded. The remote's
  locator shape differed from the assumed one and identity still matched.
- A repeated publish and a repeated observe over unchanged remote state recorded nothing
  new. One channel degraded (work tool pointed at a missing executable) left the other
  observing.
- A launchd-started pass, with no shell and no host, opened both the GitLab and JAM
  channels and detected events on each.
- A pass in which two of three workspaces failed was recorded by launchd as a failure.
- The GitLab cursor on a real workspace moved from the oldest item of its first page to
  the latest item seen, after the first pass on the new build.

## Known limitations

- **Windows and Linux registration are not exercised.** Both adapters are fixed by
  contract tests only. Neither has been run on a live machine, and this release does not
  claim they were.
- **Reboot and login recovery are not exercised.** The macOS registration runs at load,
  which is that path, but no reboot was performed.
- **No second host adapter exists.** Host neutrality is fixed structurally — core imports
  no adapter and branches on no host id — but only one host has been driven.
- **`CREATE_NEW` against a real provider is not exercised.** Every real publish attached to
  an existing artefact; creation is covered by the fixture and adapter tests only.
- **Only the GitLab surface exists.** Other providers offer no coordination surface yet and
  report the capability as unavailable.
- Duplicate request packets observed on a real workspace were measured and are not a
  defect: each pair came from two distinct remote events on the same thread. Whether a
  new mention should fold into an open packet is a design decision this release does not
  make.
- A workspace whose checkouts are all gone stops being observed and keeps its state. It
  is never cleaned up automatically, so it stays visible in `runtime list` until a person
  removes it.
- The machine registration records the absolute path of the runtime that created it. If
  that installation is removed, the registration must be removed with
  `asc runtime service uninstall`.
