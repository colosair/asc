ASC 0.5.2 fixes a first install that stopped halfway on machines whose default
Node is older than ASC requires. Everything 0.5.1 added is unchanged; this
release makes it actually happen on those machines.

## What changed

- **The entry point survives the Node re-exec.** Where the default Node is
  older than the minimum, ASC re-runs itself under a compatible Node it finds.
  That re-run started the runtime directly, so the process doing the work no
  longer knew it had come through the bootstrap door — and two things hang off
  that door. The stable global install is only planned for a run that came
  through it, and the machine registration is only offered by an installed
  runtime. A first install on such a machine attached, recorded its identity,
  wrote its bindings and canonical source, and then left no `asc` on the PATH
  and nothing registered, with no error to say so.

## Install / Upgrade

```bash
npx --yes @asc-agent/bootstrap@0.5.2 setup apply --json
```

Already installed:

```bash
npm install -g @asc-agent/runtime@0.5.2
```

If 0.5.1 left you attached but without a global `asc`, this entry finishes the
job: run it again and the install and registration it skipped are planned.

## Agent setup

The canonical entry is unchanged:

```bash
npx --yes @asc-agent/bootstrap@0.5.2 setup apply --json
```

## Compatibility

- Node 24 or newer, unchanged — and now reached correctly from an older default.
- No state schema change, no surface change, no migration.
- One new environment variable, `ASC_ENTRY`, set by ASC on the re-exec it
  performs itself. Nothing else reads or requires it.

## Verified

- Three-OS CI: typecheck, build, 1414 tests, release checks, packaging,
  packaged smoke.
- On a machine whose default Node is 22, from a cleaned state: the plan made
  through the bootstrap entry again carries the global install ahead of
  attachment, where 0.5.1 silently omitted it.

## Known limitations

Unchanged from 0.5.1: Windows and Linux registration, reboot and login
recovery, a second host adapter, and `CREATE_NEW` against a real coordination
provider are all still unexercised, and GitLab remains the only coordination
surface.
