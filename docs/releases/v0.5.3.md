ASC 0.5.3 lets the first install register the machine in the same run. Together
with 0.5.1 and 0.5.2 this completes a first install that finishes on its own:
one official entry, and nothing left for a person to repair afterwards.

## What changed

- **The first install registers the machine.** The registration is offered when
  there is a stable runtime to point at, or when this very plan is about to
  place one. It used to ask a different question — whether the *running*
  process was an installed package — and a first install comes through `npx`,
  so on a clean machine the answer was no: the plan carried no registration and
  a person had to run one more command afterwards.
- **Only a runtime that is really installed may be registered.** The candidate
  is the globally installed entry, or the running one when it genuinely is an
  installed package. A checkout offers nothing, and a temporary location was
  already refused. Registration still runs last, after the install, and
  re-resolves at that point.
- **No test may leave a registration behind.** A machine service is not
  isolated by HOME. One test that spawned setup without turning the axis off
  created a real registration whose plist was then removed with its temporary
  home, leaving a loaded job pointing at a directory that no longer existed. The
  axis is off in every test that spawns setup, and a check now fails if one of
  them stops doing it.

## Install / Upgrade

```bash
npx --yes @asc-agent/bootstrap@0.5.3 setup apply --json
```

Already installed:

```bash
npm install -g @asc-agent/runtime@0.5.3
```

If an earlier 0.5.x left you attached without a machine registration, this entry
plans it; no separate command is needed.

## Agent setup

The canonical entry is unchanged:

```bash
npx --yes @asc-agent/bootstrap@0.5.3 setup apply --json
```

## Compatibility

- Node 24 or newer, unchanged.
- No state schema change, no surface change, no migration.
- `ASC_SERVICE=off` remains the seam that keeps a verified run from touching the
  machine, and is what every test uses.

## Verified

- Three-OS CI: typecheck, build, 1417 tests, release checks, packaging,
  packaged smoke.
- On the real machine, the attached workspace's plan carries the registration
  where 0.5.2 left it out.
- The stray registration a test had created was found and removed, and the check
  that prevents a repeat fails when any setup-spawning test drops the flag.

## Known limitations

Unchanged from 0.5.1: Windows and Linux registration, reboot and login recovery,
a second host adapter, and `CREATE_NEW` against a real coordination provider are
all still unexercised, and GitLab remains the only coordination surface.
