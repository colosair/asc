ASC 0.6.0 adds `asc update`: one command that moves this machine to the
published release without redoing setup.

## What changed

- **`asc update`.** Every 0.5.x release on this machine was installed by hand —
  uninstall the old package, clear the npx cache, remove the registration, then
  re-run `setup apply`. That last step is the dangerous one: `setup` re-infers
  the profile, the bindings and the canonical source, which is a different act
  from replacing an executable. `asc update` does not call it. It installs the
  published version, proves it answers, refreshes the host installation,
  converges the machine registration, and checks health — in that order, with
  no delete step anywhere. `asc update check --json` and `asc update plan --json`
  answer without changing anything.
- **The registry not answering is not "up to date".** A failed lookup reports
  `UNKNOWN`. Reporting it as current is how a machine stays behind while
  believing it is not.
- **A version whose Node this machine does not have is refused before
  installing**, rather than installed and then found broken.
- **State is checked, not assumed.** The command records every file under
  `~/.asc` before the update and compares afterwards, and says what changed if
  anything did. Only three things are allowed to move: the installed runtime,
  the host installation, and the machine registration.
- **A failed install or verification puts the previous version back**, using the
  same install path, and says `UPDATE_FAILED_ROLLED_BACK`. If that fails too it
  says `BROKEN` and hands over the exact command.

## Install / Upgrade

```bash
asc update
```

From nothing, or if `asc` is not on PATH:

```bash
npx --yes @asc-agent/bootstrap@0.6.0 setup apply --json
```

## Agent setup

The canonical entry is unchanged:

```bash
npx --yes @asc-agent/bootstrap@0.6.0 setup apply --json
```

Updating an existing machine is now `asc update` rather than the setup entry.
ASC updates ASC only — JAM has its own `jam update`, and neither calls the other.

## Compatibility

- Node 24 or newer, unchanged.
- No state schema change, no migration. Nothing under `~/.asc` is rewritten by
  an update.

## Verified

- Three-OS CI: typecheck, build, tests, release checks, packaging, packaged smoke.
- Real machine: 0.5.4 → 0.6.0 through the published artefact, with the state
  comparison and the registered background pass checked afterwards.

## Known limitations

- `--to <version>` (downgrade, pinning a specific version) is not implemented.
- Windows and Linux updates are unexercised, as their registration paths already
  were.
- Unchanged from 0.5.1: reboot and login recovery, a second host adapter, and
  `CREATE_NEW` against a real coordination provider are still unexercised, and
  GitLab remains the only coordination surface.
