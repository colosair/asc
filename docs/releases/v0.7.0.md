ASC 0.7.0 connects lines that were already drawn. No new subsystem, no new store — the
capabilities were there and some of them were not reaching each other.

## What changed

**A physical run holds one logical session, and release actually takes.** Ownership was
atomic on the logical side only, so the same Claude session could hold two contracts at
once — measured on a real machine, that overlap happened on every round. Claiming now
looks at what that run already holds and refuses rather than taking. Release is read back
before it is reported, because the guard decides from that one file.

**Quoted text is an argument, not a command.** `git commit -m "docs: about push"` was read as
`git push`. Judgement now runs on segments split at unquoted control operators, with the
inside of `sh -c '…'` and `eval '…'` checked one level deeper. This is not a shell parser;
substitution and file-mediated execution are still outside what this layer can see.

**A run with no contract cannot write outward.** An ASC workspace used to let an unbound
session through — the reasoning was that blocking a person's own `git push` is
interference. But that opening was also there when a binding had been lost, which is
exactly when it should not be. Reads are untouched; what is stopped is what leaves the
machine, and being stopped now hands over the next step.

**A file existing is not this requirement being implemented.** Work items name paths, and
those paths usually already exist — the requirement is a change *inside* them. ASC read
"the file is on the canonical branch" as "the work is done" and told someone to stop
implementing and fix a tracker instead. Path existence is now corroborating evidence, and
`IMPLEMENTED_STALE_TRACKER` is only concluded when review says the work was accepted.
Otherwise the leaning is reported with what could not be checked — and the recommended
action never claims more than the evidence does.

**Handoff reaches the screen.** `collect` moved a session to the archive and then asked for
the active list, so the session it had just read was gone and the screen said "(no next
action)". The data was never lost. Collect now hands over what it read.

**A person's channels add up.** The identity schema is a list and the reader compares the
whole list, but the writer replaced it — so an identity captured from one channel vanished
the next time setup ran.

**The approved action goes out through whatever the profile binds.** Execution was pinned
to one provider inside the CLI while observation had been provider-neutral for months. It
now resolves through the same capability composition, GitLab included, and a grant is
refused at issue time when nothing can carry out that action — rather than after a person
approved it.

**A session's own result has a way out.** The original model only drew
`Monitor → Request → Approval → Grant`, so publishing real work meant inventing an
unrelated request to hang it on. A grant now stands on exactly one basis: an approved
request, or the session that did the work.

**Publishing outward goes through a grant.** Coordination writes had been outside that
rule on the strength of an adapter comment. Reads are unaffected.

**Attached is not the same as observed.** Two of this machine's three workspaces had failed
every background pass for several releases while looking healthy; the failures went only to
a log nobody reads. Each pass now records how it ended where that workspace lives, and the
screen says DEGRADED before it says anything about the runtime being up.

**What a person decided to do stays on the list.** Deciding `queue` on a request removed it
from the default view. The dead `QueueItem` model — schema and layout with nothing writing
or reading it — is gone; that ground is held by the request's own state and by `proceed`.

## Install / Upgrade

```bash
asc update
```

From nothing:

```bash
npx --yes @asc-agent/bootstrap@0.7.0 setup apply --json
```

## Agent setup

The canonical entry is unchanged:

```bash
npx --yes @asc-agent/bootstrap@0.7.0 setup apply --json
```

The `asc` skill now carries the publish path — what a session produced goes out through
`asc grant issue --session … && asc grant run …`, and a regression checks that every
command the skill hands over exists in this build.

## Compatibility

- Node 24 or newer, unchanged.
- **`ExecutionGrant` gained `sessionId` and `requestId` became optional** — exactly one is
  required. Grants written by earlier builds carry a request and keep working.
- **`QueueItem` was removed.** Nothing created or read it, so no stored state changes.
- `dueWorkspaces` and `renderCollect` changed shape; both are internal.
- Behaviour change to know about: in an attached workspace, an outward write from a session
  ASC does not manage is now stopped. That includes a person's own `git push` there.

## Verified

- Three-OS CI: typecheck, build, tests, release checks, packaging, packaged smoke.
- The eight incidents this release closes each carry a regression written from the measured
  failure, and five connection tests run the path end to end in one process: release →
  guard, done → collect → archive → render, work item → observation → judgement → action,
  issue → capability → run → adapter, and a failed pass → the screen.

## Known limitations

- Shell judgement is quote-aware, not complete. Substitution and file-mediated execution
  remain outside it, and the layer says so rather than claiming enforcement it does not have.
- The canonical baseline read still resolves through one provider; only the execution path
  was freed in this release.
- Unchanged from 0.6.x: no `--to <version>`, and Windows and Linux updates are unexercised.
