ASC 0.7.1 makes an update actually refresh the host, and says which session a run is
already holding.

## What changed

- **The newly installed build refreshes the host installation.** `asc update` called the
  host installer in its own process — the one that is about to be replaced — so it wrote
  that build's hook and skill text and reported success. Measured on a real machine right
  after publishing 0.7.0: update printed `host: …/SKILL.md` and finished, and `probe` still
  answered `INSTALLED_STALE` with both files behind. The guard running next to the new
  runtime was the old one, and that combination has never been tested. The refresh now runs
  through the installed executable. If it cannot be found, the update says so instead of
  quietly skipping it.
- **A binding conflict names the session it collided with.** Trying to bind a run that
  already holds another session reported that the requested session was owned by this very run, which reads as though
  the session being asked for is taken. It now distinguishes the two cases and, for the
  common one, hands over the release command.

## Install / Upgrade

```bash
asc update
```

From nothing:

```bash
npx --yes @asc-agent/bootstrap@0.7.1 setup apply --json
```

Machines that ran `asc update` into 0.7.0 have an old guard hook next to the new runtime.
This update fixes that; `asc host claude probe` confirms `INSTALLED_CURRENT` afterwards.

## Agent setup

The canonical entry is unchanged:

```bash
npx --yes @asc-agent/bootstrap@0.7.1 setup apply --json
```

## Compatibility

- Node 24 or newer, unchanged. No state schema change, no surface change.

## Verified

- Three-OS CI: typecheck, build, tests, release checks, packaging, packaged smoke.
- Two regressions: the update path does not call the host installer in-process, and the
  refresh goes through the installed executable and reports when it cannot find one.
- Found by acceptance against the published 0.7.0 artefact on a real machine.

## Known limitations

Unchanged from 0.7.0.
