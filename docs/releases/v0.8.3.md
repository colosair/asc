ASC 0.8.3 closes a dead end. On a repository whose canonical remote is self-hosted
GitLab, AUTO blocked a raw push and then had nowhere to send it — the managed executor
that could have carried it was built on every composition and thrown away unread. The
person turned AUTO off and pushed by hand to keep working, which is the one outcome this
mode exists to prevent.

## What changed

- **GitLab carries managed writes again.** The adapter implements more of the write port
  than any other — baselines, pre-write review, execution, and reading the result back
  from the remote — but it did not declare the capability that reaches the executor slot,
  and a binding is filtered on what it declares before anything examines what it can do.
  One declaration; the composition now hands the slot to the repository's own remote
  instead of to a mirror that cannot push.
- **A blocked action with no route says so, before you reach it.** `asc status` and
  `asc mode` list the actions the guard stops that the assembled write path cannot carry.
  The list is narrow on purpose: guard patterns that name a managed action, intersected
  with the actions ASC manages, minus what this composition supports. Commands that cover
  several actions at once are not counted, because "no route" would then always be true
  and the line would mean nothing.
- **AUTO is not refused over a dead end.** The other actions work. Refusing would strand
  them to protect one — a dead end pointing the other way.
- **Refusals name what is missing.** Asking for an action the assembled path cannot carry
  now answers with which binding holds the slot and everything that binding does carry,
  then points at the screen where that is listed. It does not suggest stepping down to
  MANUAL; suggesting that is how this defect reproduces itself.
- **The skill no longer refuses what MANUAL allows.** Its session-contract section folded
  two rules into one sentence — publish through the approved path (true in either mode)
  and do not write externally (which depends on the mode). As written, an agent would
  refuse in MANUAL too, where the guard deliberately blocks nothing. The person then had
  no working path in either mode: the same dead end, one layer up.
- **The two readings of the mode record are pinned to each other.** The CLI parses it
  through a schema; the hook opens the file and parses it by hand, because pulling the
  schema into the hook would make it heavy for one predicate. They agreed on every input
  and nothing checked that. A test now sends five inputs — absent, AUTO, MANUAL,
  unparseable, and a mode value that is neither — to the real hook as a process and to the
  CLI's own function, and asserts they land on the same side.

Nothing else moved. No new capability, no command surface change, no state schema change.

## Compatibility

- Node 24 or newer, unchanged.
- No state schema change, no command surface change, `~/.asc` untouched.
- **A repository with more than one remote may change which one carries managed writes.**
  Before this release only one adapter declared the executor capability, so it took the
  slot wherever it was present. Now both can, and the Profile's declared role decides. A
  workspace that declares one binding and discovers another is unaffected — discovery does
  not compete with a declaration. A workspace that declares two will see the composition
  refuse to choose and say so, which it already did for every other capability.
- `asc status` and `asc mode` can print a line they never printed before, listing blocked
  actions with no managed route. That state is not new; the reporting is.

## Verified

- Three-OS CI: typecheck, build, the full suite, release checks, packaging, packaged smoke.
- Against a real self-hosted GitLab remote, on Windows: MANUAL lets a real push through
  the whole host → hook → git path with nothing blocked; AUTO stops the same raw push both
  inside and outside a logical session; AUTO carries the push through the managed path
  end to end — pre-write review reading the remote with zero mutation, one execution, then
  the remote's own SHA read back and compared — with no mode change, no raw push, and no
  bypass anywhere in the run.
- Asking for an action the assembled path cannot carry is refused with the binding named
  and its actual actions listed, and no suggestion to lower the mode.
- The regression tests ask the adapter what it declares rather than restating it. The
  previous tests hand-wrote those arrays, which is exactly why a declaration could drift
  from an implementation without anything failing.

## Known limitations

- **The guard's push pattern matches across intervening words.** A commit message that
  contains the words is read as a command and the commit is refused; passing the message
  from a file works. Found while preparing this release, not fixed in it.
- **A development build cannot be told apart from the published one on screen**, so a
  checkout build reports the installed integration as stale and offers to refresh, which
  would install unpublished code. Unchanged from 0.8.2, and hit repeatedly while preparing
  this release — turning AUTO on had to be done with the published CLI.
- **macOS and Linux `runtime service install` have not run outside CI — for the third
  release.** Shared code carried this change too. Saying it a third time is the point.
- **The scheduled task still opens a console window each run.** Child processes were fixed
  in 0.8.2; the task itself was not.
- Published acceptance against the 0.8.3 artefact runs after publishing, not before it.
