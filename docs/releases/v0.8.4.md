ASC 0.8.4 comes from an audit of one real workspace where ASC was attached, running,
and unused. Over two days four tracked work items were completed there. None entered an
ASC session. No external write went through the managed path. The coordination ledger
was empty while real waits existed. The inbox showed a decision queue that nothing had
re-read in eighteen hours. And for twelve hours AUTO was on, during which the project
pushed nothing at all — the only thing that travelled the managed path in that window
was ASC testing itself.

Ten reasons, not one reason wearing ten faces. Each is fixed where it starts.

## What changed

- **The inbox reconciles against the origin before it shows you a decision.** `asc
  status` counts what is waiting for a person and `asc inbox` presents that list as
  decisions to make, but nothing had ever re-read the source. The transition table had
  no rule driven by external state; the only two things that moved a request were a
  person's decision and an execution result. On the machine, an issue closed 0.9 seconds
  after the request for it was created, and that request sat as awaiting approval for
  seventeen hours until someone cleared it by hand. A settled origin now moves the
  request to a new terminal state, `OBSOLETE`, which is deliberately not a decision: the
  decision field stays empty and the evidence sits beside it. Dismissing means a person
  said no. This means nobody said anything and the question went away.
- **A resource that has merely vanished moves nothing.** Disappearing from a listing does
  not say whether something was deleted, hidden, or unreadable, and those need different
  things from a person. A failed read is reported as a failed read.
- **Reconciliation asks every reader it has.** ASC does not know which provider owns a
  reference and must not learn, so it asks each one and takes the first real answer. One
  reader not knowing a reference is not the origin being gone.
- **Monitoring says whether it is current, not only whether it last succeeded.** Two
  screens described the same workspace at the same moment as healthy and as 1192 minutes
  silent. Both were true and neither was the answer. Coverage health now folds into one
  verdict — HEALTHY, STALE, NOT_RUNNING, DEGRADED, UNKNOWN — and a machine with no
  persistent registration reads as NOT_RUNNING rather than as a fault, because the next
  step is different.
- **Execution Mode is answered by the run that executes.** One session lowering the mode
  for its own acceptance released a twelve-hour AUTO held by a different session in the
  same workspace; that session noticed three hours later and recorded that it had not
  done it. A run can now hold its own answer and the workspace value is the default for
  runs that have none. This is not a new axis — the values are still MANUAL and AUTO,
  and what changed is who is asked. The mode record now carries who, which run, and why.
- **A binding names the run the guard actually looks up.** `bind` accepted any string
  while enforcement matches on the id the host hands it, so a binding made with a
  hand-written label recorded as success and was invisible forever. It now takes the
  observed run when it can see one and refuses a value that is not shaped like a run id.
  Binding a different run is still allowed, and the screen says that is what happened.
- **The same decision is not asked twice.** Event keys stop transport duplicates, not
  duplicate decisions: one thread produced two requests and the same disposition was
  recorded twice, 1.2 seconds apart. Requests now carry a decision subject and a newer
  one retires an older undecided one with the same subject. Same-issue is deliberately
  not the key — one thread can hold two different questions, and a mention is not a
  review request.
- **What was discovered and never declared is named, with the line that would attach
  it.** This is the one that closed the front door. `asc work start <KEY>` answered
  UNDECIDABLE with "missing work-item" every time, which read like a missing capability
  and was not: the tool that could answer was in the repository, discovered, and shaped
  exactly like the slot — it simply had no declaration and no screen mentioned it. Not
  available, not unavailable: absent. The list now includes candidates that are
  currently unusable, with the reason, because filtering those out is what produced the
  silence in the first place.
- **An expectation can be recorded without a grant.** The only way into the coordination
  ledger was publishing, so it stayed empty while real waits existed in real issues.
  Expectation ids are issued automatically, a single active session is assumed when only
  one runs, and `asc coordination attach` links an expectation to an object that already
  exists outside — reading it back to prove it is there and recording that as observed,
  explicitly not as a publication. Publishing still takes a grant, because publishing
  still creates something in someone else's repository.
- **The dead-end list only counts actions this workspace could take.** A repository
  declaring one provider was told on every screen that another provider's action had no
  managed route. True, and noise buries the real one.
- **Undeclared decision authority says so.** ASC refuses to guess ownership, which is
  right, but it said nothing, so investigation output read "could not determine" with no
  sign that it was fixable.

## Speed

Every command in every repository was spending about seventeen seconds asking whether a
tool was installed — in repositories that do not use that tool. Composition asked each
adapter both "is this usable on this machine" and "is this project attached to it", and
asked the first unconditionally. That separation is right and stays; paying for it when
nobody asked is what changed. The question is now asked when an adapter found a
candidate here, or when the caller wants it — `asc setup` does, because that is exactly
where a person needs "install it" separated from "attach it".

```text
a command in a repository that does not use the tool   18.5s → 0.3s
status in the workspace that does                      36s   → 15s
```

## Compatibility

- Node 24 or newer, unchanged.
- **A request can now be in `OBSOLETE`.** That is a new terminal state on the inbox
  entity. Older readers of the same state directory will not recognise it; nothing else
  about the record changed, and no existing request is rewritten by upgrading.
- **The mode record can now carry per-run answers.** A record written by this version is
  read by older versions as the workspace value alone, which means a run's own answer is
  silently ignored there rather than misread. Records written by older versions are read
  by this one exactly as before.
- One port gained an optional field for whether a resource has ended its own lifecycle.
  Adapters that do not know leave it unset, and unset never moves anything.
- `asc coordination` is on the basic help screen. Three of the four commands the audit
  found hard to reach already had public names; this one had none.

## Verified

- Three-OS CI: typecheck, build, the full suite (1658 pass / 0 fail), release checks,
  packaging, packaged smoke.
- On the audited workspace, Windows, with another session working in it at the same
  time: a work item resolved through its declared binding instead of answering
  UNDECIDABLE; a real outstanding wait recorded and attached to the issue that already
  existed, with no grant and nothing created outside; the guard refusing a raw push from
  the run that had raised itself to AUTO while passing the other live session's
  identical command in the same workspace at the same moment; a managed push through
  review, grant, execution and a remote SHA read back; one of five pending requests
  moving to OBSOLETE because its origin had closed 73 minutes earlier, with the other
  four untouched; monitoring reporting NOT_RUNNING instead of normal; the label from the
  original incident refused with the right command printed; and a session finished with
  its run released. No project-specific tooling was involved in any of it.

## Known limitations

- **The guard scopes by the session's working directory, not by the repository the
  command touches.** A session sitting in one workspace that pushes to an unrelated
  repository is judged against the first workspace's managed path, which cannot carry
  it. Hit while preparing this release; the run-scoped exit made it a non-event, which
  is the point, but the message is wrong.
- **A development build still cannot be told apart from the published one on screen.**
  Unchanged from 0.8.2 and 0.8.3. Selecting a checkout as the runtime and converging is
  the supported way through it, and that is how this release's acceptance ran.
- **macOS and Linux `runtime service install` have not run outside CI — for the fourth
  release.** Shared code carried these changes too.
- **The scheduled task still opens a console window each run.**
- Published acceptance against the 0.8.4 artefact runs after publishing, not before it.
