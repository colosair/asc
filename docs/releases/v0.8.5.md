ASC 0.8.5 comes from three threads on a real workspace that never reached the inbox. I
asked, someone answered, and nothing arrived — no notification, no assignment, no
mention. The 0.8.4 audit read this as a relevance problem. It was not one. The candidate
was never made.

The classifier's signal for it, `direct_reply`, had existed since 0.7. Its input field,
`replyToMe`, was declared on the signal context, mapped in the detector, and covered by a
unit test. Grep the tree for a production caller and there was one hit, in a test.

Everything else in this release is what fell out of making that path real: what it costs
to walk it, what happens to the items it cannot reach in one pass, and — separately — the
Windows registration that was supposed to be walking it every five minutes and was turned
off because it flashed a console window at its owner.

## What changed

**Whose turn it is, derived from the thread itself.** The observation builder now reads
the thread before it looks for a change, and takes one fact from it: did someone speak
after I last spoke. That fills `replyToMe`, which was already wired to everything
downstream. Nothing new was invented in the classifier.

The builder consulted only the change port before this — file-level facts about a
proposed change — and returned nothing at all when that port said "not a change". Every
issue took that branch. So a sweep could enumerate an issue, notice a new comment through
its revision marker, and still produce a verdict with zero signals.

**Direction is a separate question from ownership.** `INBOUND` / `OUTBOUND` / `UNKNOWN`,
from structure only: who authored it, who it is assigned to, who spoke last. The
judgement function takes no ownership, authority or decision state, and a fixture asserts
that. `UNKNOWN` stays `UNKNOWN` — nothing promotes it to "your turn". Assignment alone
does not make something inbound either; someone has to have spoken.

**What already dealt with it, checked against the ledgers we have.** When an answer
arrives, the screen says whether anything happened after it — a coordination response, a
disposition on the same resource, an execution against that target — and counts only
records dated after the answer. Where nothing is found, it says where it looked. Where
ASC has no ledger for it at all, the answer is that it could not tell, and it says so
rather than reporting an absence it did not establish.

**Reading threads has a budget, and the budget is honest.** 40 per pass. An item over
budget is not recorded as seen, its event row is not written, and the coverage baseline
stops behind it — three separate places, each of which alone was enough to lose it. The
sweep result carries the count and the screen prints it, because "the listing completed"
and "everything in it was opened" are different facts and only one of them was being
reported.

**The listing is not asked twice.** Judging direction needs the comments, the author and
the assignees. The last two arrive in the listing response and were being thrown away, so
the observation made a second single-object call for them. Measured, that was half the
cost of a pass.

**Items I opened or was assigned are read first.** With a finite budget, order decides
whether an answer to me is seen today or tomorrow. Nothing is filtered out — a thread I
joined only by commenting looks like anyone else's from the listing alone, and dropping
those would trade a cost problem for a correctness one.

**A scheduled pass no longer flashes a console window.** `node.exe` is a
console-subsystem program, so Windows creates a console for it whether or not anything is
printed; Task Scheduler's `<Hidden>` only hides the task from a list. At a five-minute
interval that is a window every five minutes, all day. The person who reported it had
turned the registration off, which is the correct response to a tool that interrupts you,
and is why persistent monitoring was not running on that machine at all. The task now
registers `wscript.exe` — a GUI-subsystem host — against a generated script that starts
the real command hidden. Its output goes to the service log, which on Windows it was not
doing before.

**The guard says which workspace judged, and stops offering a path that cannot help.**
It scopes by the session's working directory, which is defensible — a shell line does not
reliably say which repository it will touch. Offering *this* workspace's managed path for
a write heading somewhere else was not. Where the command names a target and that target
is not here, it says so and drops the suggestion. Where it cannot tell, it says nothing
about the target, keeps the managed path as a conditional, and still blocks.

**Sessions paused and never returned to are named.** Paused, no run holding it, quiet for
a day: `asc status` says so, with the evidence and both commands. It does not choose.
Whether a contract is finished is not something the absence of activity can tell you.

**`asc host claude bind` refuses a session that does not exist.** It used to create the
binding and say the session was now managed. That binding then held a run and blocked the
next bind.

**Two screens tell the same story about execution mode.** A run with its own answer says
so in `asc status`, not only where it was set.

**The `profile.lock` version notice moved.** A lock written by an older ASC blocks
nothing, so it had no business printing from the gate nearly every command passes
through — twice per invocation in practice. It is a line in `asc status` now. Real drift
still stops the command.

## Speed

One pass over the audited workspace — 685 objects, nothing yet in the coverage ledger:

```text
0.8.4                     16 API calls     71 s
first cut of this work   422 API calls    364 s
shipped                   56 API calls    124 s
```

The middle row is why the budget is 40 rather than 200 and why the listing is not asked
twice. A steady-state pass on the same workspace is 4–7 calls and about 17 seconds.

## Compatibility

- Node 24 or newer, unchanged.
- **A request's source can now carry `direction` and `lastOtherAt`.** Both optional.
  Older readers ignore them; nothing existing is rewritten.
- **A coverage record can now carry `direction` and `lastMineAt`.** Also optional, and a
  pass that does not know the direction leaves the previous value alone rather than
  clearing it.
- **The inventory port gained an optional `author`.** Adapters that do not know leave it
  unset. GitLab and GitHub already had it in the listing response; JAM does not expose a
  reporter, and its single-object read did not have one either, so nothing is lost there.
- **Windows registrations from before this version read as stale** and are replaced on
  the next install. They invoked `node.exe` directly; the fingerprint now covers the
  launcher, so a build that changes only the launcher is noticed.
- Observation builders gain an optional `startPass`. Anything that supplied a plain
  function still works.

## Verified

- Three-OS CI: typecheck, build, the full suite (1726 tests, 1724 pass / 0 fail / 2
  skipped), release checks, packaging, packaged smoke.
- **On this Windows machine, for the registration**: installed, `schtasks /Run`, zero new
  visible windows; the pass ran and appended to `~/.asc/service.log`; `asc monitor status`
  reached HEALTHY. Turning the log on immediately showed seven of eight workspaces exiting
  2 — six of them temp directories that no longer exist — which nobody could have known
  before, and which is not fixed here.
- **On the audited workspace**: a paused session three days quiet named in `asc status`
  with its checkpoint and both commands; the inbox naming, per request, what it checked
  and what it could not tell; the cost figures above, measured against 0.8.4 on the same
  workspace within the same hour.
- **An independent review** against the design invariants found three violations in an
  earlier cut of this work, all in the same place: an item the budget skipped was being
  recorded as seen through two paths I had not found, and the fixture that was supposed to
  prove otherwise was asserting the symptom. Fixed, and the fixtures now assert which
  threads were actually opened.

## Known limitations

**An answer consumed entirely outside ASC still surfaces once.** Consumption can only
check ASC's own ledgers. The real case that prompted this — a reply dealt with in a
conversation ASC never saw — will appear in the inbox, and the screen will say it checked
the coordination ledger, the dispositions and the execution records and found nothing
after the answer. Removing that would mean guessing at facts ASC does not have.

**The guard's scope did not change.** It still judges by the session's working directory,
not by what the command touches. Only the message changed, and only where the command
names its target explicitly with `-C`.

**A deferred item returning was not reproduced on the real machine.** It is pinned by
fixtures that fail without the fix — including one with a change port attached, which is
the composition every merge-request channel uses — but the real workspace could not be
returned to a cold state to watch it happen end to end.

**Threads I joined only by commenting are read last.** They are not dropped, but on a
large first pass they will be several passes behind the ones I opened or was assigned.
The listing does not say who commented, and asking would cost the call this release just
removed.

**Seven of eight workspaces fail their scheduled pass on this machine.** Now visible in
the service log, not addressed. Six are temp directories from testing that the index
still lists; the seventh has no approver configured. Nothing prunes a workspace whose
directory is gone.
