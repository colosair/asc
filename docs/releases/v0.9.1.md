ASC 0.9.1 is the follow-through on 0.9.0. The published acceptance of that release and
the audit behind it left a short list: one upgrade message that never reached the screen,
one flag that was parsed and then silently thrown away, one review that ran without a
basis when it should have refused, a handful of sentences that still claimed more than
the 0.9.0 threat model does, and three pieces of code that nothing called any more. This
release closes that list and adds one gate to the release procedure itself, because 0.9.0
was tagged six minutes before its own acceptance record landed.

Nothing here changes a persisted schema, the resource identity model, or a Core public
type. The guard stays gone; nothing intercepts the shell under any other name.

## What changed

**`asc update` now says what it retired.** The 0.8.x → 0.9.0 upgrade removed the guard
hook correctly and printed nothing about it: the new build's `asc refresh` output was
forwarded through a line filter that knew `installed:`, `skipped:`, `service:` and
`Install state:` and dropped `removed:`. The filter passes it now, and a CLI-level test
spawns `asc host claude install` on a 0.8.x-shaped home and asserts the `removed:` lines
on stdout — the producer side the unit fixture never exercised.

**`asc session issue --done` is refused instead of ignored.** The CLI has one option
table for every subcommand, so `--done` — the pause/done flag for *tasks already finished*
— parsed cleanly on `issue` and was never read; the session came out READY with empty
done criteria. The command now stops before writing and names the right flag. There is no
alias: done criteria go on `--criteria`, which is what every machine producer
(`session plan`, `work start`) already emits. The usage line for `session issue` lists the
flags it actually accepts.

**A review that cannot pin its target does not run.** When a Profile declared two
bindings for the same adapter, `bindingIdentity` returned nothing, the pre-execution
review ran without a resource basis, `BINDING_MISMATCH` could never fire, and a grant was
issued unscoped. That state is now named (`AMBIGUOUS`) and `asc work publish --review`,
`asc work publish` and `asc grant issue` stop before reviewing or issuing, saying which
bindings collide and what to do: narrow the Profile to one binding for that adapter, or
wait for explicit multi-binding selection in 0.10.0. ASC does not pick one. One declared
binding, or none, behaves exactly as before. The judgement lives in the CLI; the Core
identity model is untouched.

**Dead policy and rendering surfaces are gone.** `policy.evaluate`, `denyResponse`,
`PolicyQuery`, `PolicyDecision`, `Verdict` and `scope.pathInScope` had no production
caller; the invariants they described are enforced where they were already enforced —
HARD DENY escape and scope escalation when a session is issued, external writes by the
grant's `allowedWrites` and the pre-execution review. The C-03 §5.4 test now pins those
issue-time checks. No edit-time path check was added. `RenderInput.liveness` lost its
only producer with the 0.9.0 heartbeat retirement and is removed with its branches.
`packages/runtime/scripts/dist-smoke.mjs` asserted that `--help` contains `asc proceed`
(false since 0.8.0), was not wired to CI, and would have thrown; the tarball smoke covers
what it did.

**Wording matches the threat model everywhere active.** The executor header no longer
calls itself the only place external writes happen — it is the only place *ASC-managed*
writes happen. The skill's publish paragraph says "nothing ASC executes reaches an
external system", the runtime package's npm README no longer lists an external-write
guard, C-01's gate table scopes "external write safety" to ASC-managed publishing, the
workspace-index comments name the SessionStart hook as their strictest reader, and
`asc help --advanced` marks `asc proceed` and `asc progress show` as deprecated. The
bootstrap plan's next step is `asc work start`. `OperatorDeps.guard` gains one comment
line saying it is the bootstrap/profile.lock check and not the retired hook; the rename
waits for 0.10.0, where `bootstrapGuard` and C-03 §1.2 can move with it.

**finalize refuses a tag without an acceptance record.** The release-finalize workflow
now reads `docs/release/v<V>-checklist.md` at `main` HEAD — where the record lands by
construction, after publish — and stops unless it has an execution-record section (the
checklist's Korean heading for the run). Unchecked boxes are not the signal; "not taken"
is recorded as `[ ]` on purpose. `dry_run` reports instead of failing.

## Install / Upgrade

```bash
asc update
```

From nothing:

```bash
npx --yes @asc-agent/bootstrap@0.9.1 setup apply --json
```

Upgrading from 0.8.x goes through the same retirement 0.9.0 introduced, and this time
`asc update` prints the `removed:` lines.

## Agent setup

The canonical entry is unchanged:

```bash
npx --yes @asc-agent/bootstrap@0.9.1 setup apply --json
```

## Compatibility

- Node 24 or newer, unchanged.
- **`asc session issue … --done <x>` exits 2.** It used to exit 0 and drop the value. Put
  done criteria on `--criteria`.
- **`asc work publish --review`, `asc work publish` and `asc grant issue` exit 2 when the
  Profile declares more than one binding for the executing adapter.** They used to run
  the review without a resource basis and issue an unscoped grant. Profiles with one
  binding per adapter — the only shape the resolver ever pinned — are unaffected.
- **`asc update` output gains `refresh: removed: …` lines** on hosts that still carried a
  retired artefact.
- **release-finalize requires an execution-record section** in the version's checklist
  on `main`. Maintainer-facing only.
- State schema, Profile schema, grant `basis`, session entity: unchanged. No migration.
- Removed internal code (`policy.evaluate` family, `pathInScope`, `RenderInput.liveness`,
  `dist-smoke.mjs`) was not part of the package's public surface, which is
  `dist/cli/asc.js` alone.

## Verified

- Three-OS CI: typecheck, build, the full suite (1677 tests, 1676 pass / 0 fail / 1
  skipped), release checks, packaging, packaged smoke.
- **Session issue.** CLI-level: `--criteria` round-trips into `doneCriteria` and shows in
  `session audit`; `--done` exits 2 before anything is written and names `--criteria`;
  `help --advanced` lists `--criteria` on the `session issue` line.
- **Binding identity.** One binding pins, none is NONE, two are AMBIGUOUS with both
  resources named; the publish path refuses before `review()` is called and the grant path
  refuses before `issueForSession`, asserted against the CLI source so neither can drift
  back to a silent `undefined`.
- **Upgrade output.** `asc host claude install` spawned on a 0.8.5-shaped `~/.claude`
  prints `removed: …/guard-hook.mjs` and `removed: …settings.json (PreToolUse hook entry
  retired)`.
- **Unchanged invariants, still green:** work start binds the current Run and exits 1 on
  a conflict without taking over; no PreToolUse hook is installed and a 0.8.x one is
  retired with user hooks untouched; MANUAL/AUTO keep their meaning and readiness is
  executor + control-plane; the executor checks the freeze before CLAIM; grants are
  one-shot; drift refuses; exactly one mutation; read-back; `glab --hostname`; push to
  the discovered remote; deprecated aliases still answer.
- Published acceptance on this maintainer's macOS host is recorded in
  `docs/release/v0.9.1-checklist.md` under its execution-record section, merged to `main`
  before the tag — the first release under the new finalize gate.

## Known limitations

**Resource identity is still path-only.** Two bindings for the same adapter are now
refused rather than silently merged, but a single binding whose path exists on two hosts
is still told apart only by which remote discovery saw first. `host/path` identity, the
discovery dedupe that keeps the first host, and explicit multi-binding selection are one
design item for 0.10.0.

**GitHub has no pre-execution `review()`.** Its only managed action is an API comment;
no resource fact is produced, so `BINDING_MISMATCH` cannot fire for GitHub targets.
0.10.0.

**Three deprecated aliases are due for removal.** `asc init`, `asc proceed` and
`asc progress show` were deprecated in 0.8.0 under a two-minor-release policy. They still
answer here, marked in `help --advanced`; 0.10.0 removes them.

**`OperatorDeps.guard` keeps its name.** It is the bootstrap/profile.lock check and the
comment now says so; renaming it alone would split the term from `bootstrapGuard` and
C-03 §1.2, so it moves with them.

**The canonical-source proposal at setup still defaults to `origin`.** It is a proposal a
person edits, not the executor's remote (which follows discovery since 0.9.0). 0.10.0.

**Windows is covered by CI only, again.** The one Windows-specific corner 0.9.0 added —
retiring an *unmarked* 0.8.x PreToolUse entry by exact command-string match — depends on
`homedir()` spelling identical to the 0.8.x install. Marked entries are spelling-independent
and CI-covered. The checklist carries a Windows acceptance line; if it is not taken, it is
recorded as not taken.
